### Scope and stable contract changes

1. **Logical source identity and retirement.** `import-identity.ts` identifies a part from filename, selected destination and sorted logical locator fields, explicitly excluding original/image asset hashes; CSV product rows retain product-ID identity. Reimport revises the existing source ID. Import execution retires removed positions and superseded duplicates from the old implementation with a new `removed: true` source version. Repository invalidates approved references, rejects new draft/publication references to removed sources, and learner excludes them. Original text, assets and source-version history remain available. Returning to previously imported bytes updates/revives the same logical source rather than being skipped by historical content hashes. Same-name files within one destination are replacement material; preview explains invalidation and rejects simultaneous ambiguous same-name replacements. A persisted document lease rejects outdated plans for the same import destination set.
2. **Original registration versus shared blob.** `original-file:<sourceId>` records immutable name/extension/mimeType; parser selection uses registration metadata with original source-label fallback for older registrations. `addAsset` returns existing content-addressed metadata unchanged. Raster/learning reuse cannot rename or demote the original. Learning transmits its verified PNG tiles with PNG MIME regardless of a previously shared blob display type. Real image import → parse → estimate → completed model-port learning → repeated preview preserves metadata and works, including identical bytes registered under another filename.
3. **Terminal lifecycle.** `resolveUncertain` only accepts `needs-confirmation` with a submitted checkpoint. Both retry and skip reject cancelled/succeeded jobs without changing status, revision or checkpoint, and without new model calls. UI hides recovery for terminal/running/paused states; cancellation copy no longer invites recovery. Existing explicit nonterminal retry/skip behavior remains covered.
4. **OCR and non-text relationship evidence.** `knowledge-evidence.ts` defines `image-text` and `visual-relationship`; main `learning-evidence.ts` checks owned imageAssetId and exact page/image/tile provenance, restricts relationship categories to visible spatial/arrow/connection relations, and requires generated answer to match its OCR quote or direct observation. Prompt prohibits hidden specifications, function/causal/operational inference and cross-tile guessing. Text-only evidence/answers remain contiguous source excerpts. `KnowledgeVersion.modelEvidence` persists alongside the exact source revision in SQLite/history and is retained by ordinary draft editing. `KnowledgeVisualEvidence.vue` shows the evidence plus exact image in the review editor through the existing asset callback. Image preview buttons are explicitly non-submit when embedded in that editor. No automatic publication or correction learning was introduced.

Optional domain additions for Task5: `KnowledgeSource.removed` (missing means false for existing data), `KnowledgeVersion.modelEvidence` and the same optional editable draft field. Retain source history and evidence JSON in future recovery/backup work. New main helpers are `import-identity.ts`/`learning-evidence.ts`; shared evidence schema and dedicated evidence component keep logic out of the manager controller (its only change is forwarding one existing-version field). Existing pipeline actions and configured model transport are unchanged.
