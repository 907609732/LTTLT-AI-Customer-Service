## 使用与数据

1. 在添加店铺中输入名称并选择拼多多或抖店；添加后AI关闭。
2. 点店铺“打开”，自行完成平台登录。抖店需要本机已安装客户端；遇到连接问题可重启客户端。
3. 在“模型接口设置”选择 DeepSeek 或通义千问，仅粘贴对应 API Key 后测试并保存；接口及默认模型自动填好。千问默认百炼北京地域。自定义/本机模型通过高级设置调整；转人工关键词在配置中心设置。密钥只保存到主进程safeStorage；不可用时拒绝明文/可逆base64降级。前端只取得是否已配置。
4. 模型规则保存应用于全部店铺；AI必须显式开启，每次启动重新关闭。停止/暂停会取消未发送的在途生成与延迟发送。人工发送先取消该会话AI在途回复，其它会话继续；可显式恢复本会话AI。
5. 选择实际采集会话后才能人工发送。发送未确认时请先在平台核对，避免重复。

正式数据放在当前应用userData/backend内；不擅自迁移或覆盖原desk-v1用户数据。会话历史有条数限制，保留本地文件；不得提交真实配置、密钥或客户聊天。测试全部使用临时数据目录。浏览器dev:web入口没有Electron主进程，只供离线设计预览。

## 代码边界

- electron/backend.cjs：复用Config、StoreRegistry、ReplyEngine、MessageMonitor、AiClient、SecretStore，提供command/snapshot/event，维护选中店铺和会话存档。
- electron/platform-host.cjs：平台适配器、独立平台窗口、回环抖店桥接、客户端启动器。
- electron/main.cjs、preload.cjs：仅可信主/辅助窗口的主框架可访问白名单管理接口；平台窗口和外来页面拒绝管理IPC。
- BackendProvider/BackendLayers：快照订阅、源图层业务数据区域、实际会话、必要设置表单；FrontendControls把保存请求接入服务层。
- desk-v1回复引擎新增运行代次与会话人工接管校验；关闭时阻止迟到的启动与监控恢复。

依赖zod升至4.6.7并通过原配置/注册表测试；修复原3.x版本对应GHSA-mrhx-c7xc-m3w5，同时保留electron-builder已有构建依赖的中等级审计项，未盲目降级构建链。

## 验证边界

已运行原后端127项单元测试、前端/接线/草稿测试、107项浏览器检查。实际Electron验收添加店铺、配置写盘与重启回读、跨窗口规则同步、受控消息到辅助窗口、离线发送拒绝保留输入、取消关闭和外来页面IPC拒绝。受控适配器单元测试验证实际服务人工发送到精确storeId/uid和成功存档。

尚未扫码登录真实店铺、调用真实AI服务或向真实买家发送。平台采集/发送完整可用性需要用户登录后再验收，不能把fixture或离线检查当作平台生产验收。

正式构建与打包仅在GitHub Actions进行；同次产物下载、哈希与本机运行结果以交付记录为准。
