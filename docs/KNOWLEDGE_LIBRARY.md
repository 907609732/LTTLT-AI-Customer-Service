## 清除后的自动重启（1.0.19）

继续先自动备份、校验和用户完整确认，再清除知识范围。正常完成会在进程内重建服务；回滚成功也不会重启。仅当确认清除后的重建及回滚重建均失败，主进程所有者调用 Electron 原生 app.relaunch()/app.quit() 自动重启一次，不再要求用户手动操作。复用 before-quit 的运行时退出队列、不等待同队列内的关闭，避免死锁；保留原工作目录、启动参数、userData 与登录分区，无新增 IPC 或 AI 操作入口。重启失败明确提示并保留恢复点，不伪报清除成功，不自动再次执行清除。

参考：[Electron app.relaunch](https://www.electronjs.org/docs/latest/api/app#apprelaunchoptions)。复用项目既有 Electron 43、知识替换/回滚和退出生命周期，无新增依赖。

本店范围保留他店共享知识、来源依赖和未审核草稿，仅撤销本店应用及私有知识/商品关联、任务和待学项。公共模板仍可在列表查看，重新应用需要用户编辑与审核。缩减模板范围只复制已有已审核内容及审核记录，不审批新事实；原版本保留。无他店依赖的本店来源标为移除，其余来源保留供他店核对，全部旧本店来源记录clear标记，不再作为本店新采集/导入的去重或更新对象。已清除物理绑定允许一次受控重新采集，版本递增且不会重新启用撤回的私有知识。账号全库清除知识表、历史/审核索引和兼容记录，但设置、迁移完成标记、备份及磁盘原件保留；该功能不是安全擦除。店铺注册、平台登录与模型配置不在知识库清除范围。

当前账号 `managed.dataDir/knowledge.sqlite` 是知识唯一写入仓储。`local-runtime` 在旧服务构造前注入 SQLite 兼容端口，旧商品/意图保存和导入只生成草稿；既有明确人工纠错路径可以发布。原 JSON 是迁移输入，不能被旧构造器继续写回。迁移失败保留原文件与备份，库进入只读诊断，正式回复和试问暂停。现有 `%APPDATA%/yunduo-ui-restored`、登录分区和 appId 保持兼容。

发布验收补充：托管账号尚未登录时允许主进程装配任务服务，实际知识请求仍校验账号租约，关闭后的服务不得重新注册。旧训练入口的商品识别从当前活动根绑定及有效、已审核的商品知识读取，不依赖旧商品行的启用标记；仅店铺通用知识、草稿、撤回、来源变化、过期或解绑均不能使商品获得训练资格。此兼容读取只提供商品身份，商品事实继续由统一知识上下文检索，不复制旧描述或价格。

Windows 深层账号目录通过 Node 内置 `path.toNamespacedPath` 交给 SQLite，包含主库、备份快照及恢复校验/合并库；文件系统位置、账号哈希目录和恢复守卫不变。此修正覆盖账号切换后超过常规 Win32 路径长度的情况，不通过缩短测试目录或迁移用户资料规避。

店铺侧栏“导入知识”和配置中心“查看商品”打开同一个独立 `#/knowledge` 窗口，携带明确店铺上下文；窗口内切店不改变接待页当前店铺。关闭管理窗口先保存草稿再隐藏；保存失败留在编辑器，提供重试、放弃或继续编辑。窗口关闭不取消后台任务，应用退出和账号切换才关闭服务。

商品根卡片按 SQL 分页，每页20件；只读取轻量摘要，图片进入视口后按资产ID加载。卡片显示实际采集的SKU数、规格、动态采集时间与TTL状态，移除的来源保留历史但不计为当前来源。通用问答、待审核、任务、待学问题和设置均在同一窗口。原件登记只表示字节已保存，实际解析内容和处理结果以子资料及任务为准。

草稿自动保存与人工审核发布分开。审核展示范围、精确来源版本、有效期与受影响店铺；批量结果逐条保留成功、跳过和失败。可编辑/排除模型候选，查看问答版本历史及来源历史。公共模板显式选择店铺应用；“为本店创建覆盖”保留模板并生成独立条目，动态覆盖有有效期。

一个共享商品可绑定多个店铺根商品和SKU。编码、标题和规格相似度只产生同款建议，必须人工选中并确认全部根商品/SKU版本集合后，才能事务重关联。物理店铺/商品/SKU身份、来源、本店覆盖和动态差异保留；不允许单SKU跨共享商品改向。默认“解除关联”仅解除本店根商品及其SKU，其他店铺保留。详情内“从全库移除此共享商品”另行列出全部影响范围并确认，撤回引用、取消相关任务，历史仍保留；撤回后不能通过旧草稿重新发布，恢复须用备份。

## 只读采集、日检与动态值

唯一 `knowledge/pipeline` 协调器注册 collector 与 source-pipeline。目录优先：复用既有拼多多 provider、登录分区、原生在售筛选和独立WebContents，先核对身份与实际目录，再选ID或已验证的“筛选全部”。身份、页范围、游标及30分钟范围令牌只留在主进程。未知总数、重复页、缺页或平台限制明确为部分范围，不能把首屏当全店。每任务最多1000商品，目录最多1000页/10000行，超范围拒绝而不静默截断。

原料分为目录/raw/capture、稳定静态、图片及本店SKU动态来源。静态变化只使相关来源依赖的已审核问答失效，手工无依赖知识不受影响；动态更新不撤回不相关静态知识。动态值使用原采集时间，默认60分钟TTL，可设置。完整快照确认SKU不再列出时撤回旧动态依赖但保留物理身份，未经验证的缺失不猜价格/库存。

图片仅允许当前已验证详情的HTTPS平台CDN URL，通过当前店铺Session读取，禁跳转，10MB/图、50MB/商品，核对安全位图MIME/字节。超过图片URL缓存容量时先淘汰旧页，保留刚验证的当前页。失败、平台900009及受限详情保留具体原因；验证码、登录或身份变化暂停待人工。平台采集不调用模型、不发布答案。

拼多多素材轮播按槽位读取背景主图，忽略同槽位的 AI 角标；旧布局以 URL 去重，兼容预加载和懒加载图片。槽位缺图或实际数量与页面声明不符时，仍不会标记为采集完成。

日检默认关闭，每次启动或重建账号运行会话后均需手动开启，旧账号此前保存的启用状态不自动恢复。启用后的检查时间默认为每天09:00（Asia/Shanghai，可设置），只在应用运行且账号/店铺已可用时检查已关联根商品。每天每店独立持久化检查日：错过09:00或同日稍后登录只补一次，其他店已检查不妨碍新登录店。日检复用 `quiet:true` 采集器，只读取/比较，不抢焦点、不启用AI、不调用模型。未解决的暂停/验证码日检阻止自动重复，须手动继续或取消；应用退出后未完成任务保持暂停。应用关闭时没有系统后台定时服务。

## 文件、聊天与模型学习

商品详情“原始资料 / 来源版本”→“导入本商品资料”明确绑定该物理商品。顶部“商品CSV / 通用资料”无商品目标时预览本店通用范围。主进程原生选择器持有路径，渲染端只收到不透明 sourceIds。原始字节按SHA256保存一次；PDF每页文本/栅格、DOCX文字及内嵌图、XLSX所有sheet、CSV逻辑行、文本行、聊天消息ID均保留位置。

TXT/MD/CSV/JSON支持BOM、严格UTF8、可验证UTF16或GB18030；预览显示编码。CSV按显式商品编号逐项映射，商品行不会变成一个巨型资料；其他列仍保留原件。导入的启用/审核标记不受信，结果均未审核。聊天可导入JSON消息，或显式选择日期后导入本店现有归档；每会话最多现有100条，媒体只计数，不主动抓平台全部历史，不自动把店铺服务承诺提升为共享商品知识。

PDF/DOCX不在业务preload页面执行。图片/扫描页分块不超过1400×1400送当前视觉模型，GIF仅首帧。图片展示仅使用主进程验证的位图资产。原文件可能包含多商品行，原件始终完整保存。

同名文件在相同目标代表更新：逻辑文件/页/图片/分块/行位置决定来源身份，内容hash只标识版本。消失的位置写 `removed: true` 历史版本、使旧审核结果stale，不删除审计。独立 `original-file` 元数据保存原文件名/扩展名/MIME；`import-item` 与 `import-document` 身份/租约保存于同一SQLite。图片文字或直接可见的位置/箭头关系候选保存 `modelEvidence`（本次实际图片资产与page/image/tile），编辑/审核可打开依据；这不等于真实模型语义正确。

学习先估算并固定来源/绑定/模型能力版本，再由用户明确开始。每次使用现有cl100k BPE，输入估算≤8192、每图预留1536、输出maxTokens4096；分块保持完整证据。当前本机加密Key或托管chat计费端口复用，不要求开店铺AI，不提供发送或自动发布。托管输出仍受既有服务策略约束。

任务先持久化并返回jobId，再异步I/O，不占工作区命令队列，也不在网络期间持有SQL事务。调用前写submitted，响应后写received，候选与完成索引事务保存。submitted不确定结果必须明确retry（可能重复计费）或skip；普通resume不会重放，received保存失败仅复用已有响应。取消、暂停、移店、退出中止在途调用，迟到结果不入库；重启不自动重放，cancelled/succeeded不可恢复。

## 正式回复、试问和待学问题

正式回复、训练及试问使用同一审核检索器：先按本店明确商品ID或唯一精确标题定位，既有SKU选择器只用于身份识别，原始平台JSON不灌进请求。按店铺、商品、SKU、覆盖和有效期筛选，再检索完整知识条目。完整条目超预算会被排除并报告，不裁剪证据。

正式回复/训练保留既有16K触发、8K目标压缩流程；知识低层 `complete` 额外按同一计数规则在worker线程计算全部输入，≥16384估算token直接拒绝，问题和条目不静默截断、不发模型。稀有字BPE仍可能耗时约21秒，但主线程保持响应，可取消，60秒超时拒绝；没有改写tokenizer。学习继续使用自己的8192分块预算。

引用绑定同次resolution与精确trace，批准门以及适配器逐字输入、最终点击均重新验证。撤回、来源变化、覆盖、解绑或过期会阻止旧候选发送。实际基线为 main `f2193fc`：保留用户已授权的每店审核/自动发送模式，将知识验证放入既有发送门，不回滚模式、不自动启用AI。恢复重建遵循现有启动AI关闭规则，店铺模式设置保持。

只有显式 `purpose: reply` 的真实买家uid及实质问题，且无完整有效知识覆盖，进入待学箱；记录未知商品/过期字段/无有效知识原因，按账号、店铺、商品/SKU、NFKC规范问题去重并累计次数。保存最多6条上下文、每条600字和有界会话ID。礼貌寒暄排除，但“价格/尺寸/多久”等短问题保留。预算排除条目、试问、训练、网络异常文本不记成新知识缺口；已独立确定的真实缺口不依赖模型网络成功。

## 导出、备份和恢复

“导出JSON/CSV”是当前店铺/选定共享商品的兼容文字导出，包含当前草稿、显式商品/SKU、字段/有效期；导回支持的预览后仍是未审核草稿。PapaParse负责CSV引号、换行、UTF8BOM及公式转义，格式标记支持准确回读被转义字段。附件、历史、发布状态应使用备份，不把兼容导出称为完整备份。

“全库备份”通过 SQLite `VACUUM INTO` 获得一致快照，并依据快照登记资产生成文件hash/size清单。“同款备份”是真正的canonical family子集：全部店铺/根商品/SKU，所有保留条目的版本/审核/来源历史、removed来源、视觉依据资产、原件及导入身份依赖。跨商品历史依赖会明确作为依赖保留；完整原件可能包含其他商品行。不是单店副本，也不是伪装成单品的全库复制。

“恢复备份”由主进程选择目录，校验清单、hash、SQLite完整性/关系、当前与历史版本一致、每个已审核版本对应有效审核记录（含legacy-preserved）、引用、资产和范围闭包，再给出10分钟一次性不透明预览token。预览合并备份与当前库，逐项标记恢复、停用（保留历史）或移除，包含备份后新增的其他店铺/SKU以及全库替换时当前独有资料的店铺，显示店铺/关联/知识/来源数量、原件和停止服务影响；提交前再核对文件指纹、当前库revision与账号租约。渲染端不能指定任意文件路径。

真正恢复由 `WorkspaceRuntime.restoreKnowledge` 所有者串行执行：保留完整恢复点→旧租约不可用→停止模型/采集/后台服务→关闭实际唯一SQLite writer→暂存校验/替换→用同一账号factory重建全部兼容端口与服务→管理窗切到新workspace。不能只调用 `KnowledgeRuntime.dispose()`，也不通过切换模型来源或AI设置强制重建。替换完成后的运行时启动异常可回到恢复点并重建；替换中途留下持久意图时保持不可用，必须按下文维护步骤处理，不能自动覆盖中断现场。

同款恢复合并到关闭后的当前库副本，保留其他family及已迁至其他family的当前条目/历史；不可悄悄重定向相同物理ID。共享依赖与当前其他商品不一致则拒绝覆盖。备份后新增的同款绑定保留身份审计但变为未关联。全库恢复替换知识库，不创建店铺注册信息；已有活动店铺范围须在当前账号内。资产按内容地址追加保留，恢复点与旧数据库归档不自动删除。

## 2026-11-15 最终审查修正

长问题保持完整原文；自动冲突键仅在超过300字符时使用完整问题JSON编码的SHA256，不截取前缀。现有短键及显式覆盖关系不变。启动时在唯一writer事务中识别历史 `conflictKey === question` 且超过300字符的已知自动格式，同时修复当前草稿、审核版和全部历史版本；不重发审核、不改来源引用或审核记录。问题仍限4000字符，显式键仍限300字符。已经生成且含旧超长键的备份仍被严格拒绝：本轮只修复旧live状态并重新生成有效备份，不改写旧archive或放宽备份校验。

编辑器只显示共享canonical条目和当前店铺、当前商品及其SKU覆盖，保存前再次核对范围；完整家族绑定仍用于同款关联和受影响店铺预览。共享条目引用的B店来源即使不在A店商品绑定下，也出现在A店原始资料对照及来源页，明确标记“来源店铺”和共享引用。无关B店私有覆盖不会混入A店编辑器。知识历史属于具体条目/草稿会话，切换、新建、放弃会清空，旧会话迟到结果丢弃。

## 恢复中断维护步骤

替换前先flush暂存库、安装副本及固定 `knowledge-restore-intent.json`；替换所有路径均在主进程解析后的当前账号根目录内生成。主库、WAL、SHM移入 `knowledge-pre-restore-*` 后再安装新库。只有完成替换才清除固定意图；任何替换中断都保留原库片段与完整暂存库，下一次仓储构造在 `DatabaseSync` 和旧JSON迁移之前拒绝启动。空白或损坏意图同样拒绝，不读取其中路径执行恢复或删除。主入口显示专用停止启动对话框及可信账号目录，不显示任意异常正文。

1. 用户保持应用关闭，完整复制对话框所示账号目录，包含 `knowledge-recovery`、assets、意图、暂存库、旧库归档及现存主库/WAL/SHM；保留原目录，不删除任何标记。
2. 维护人员只在该完整副本上检查。优先使用 `knowledge-recovery/knowledge-*` 中本次操作前的完整快照，由现有 `inspectKnowledgeBackup` 验证原manifest的hash、版本、审核、来源及资产闭包，并与用户确认应恢复的版本。不能仅凭最新文件名猜选版本；意图中的文件名只是线索，禁止解析到账号根外操作。
3. 将副本内的意图和半完成live三件套移到副本内独立保留目录，保留对应归档与暂存文件；再对副本调用已有 `restoreKnowledgeBackup({ directory: 副本账号目录, backupDirectory: 已验证快照目录 })`。完整快照restore不与旧WAL混用。以隔离运行时启动该副本，复核店铺/商品/版本/审核/来源/附件，并重新生成通过校验的完整备份。
4. 若没有可验证完整快照，保留全部片段交由SQLite离线恢复处理，不拼接新库与旧WAL、不删除意图强行启动。只有副本验收且用户确认版本后，才另行安排原账号恢复；本次实现和测试未执行用户数据恢复。

本轮真实强制终止测试覆盖旧主库、WAL、SHM移走和新主库就位四个边界，随后全新owner启动均拒绝创建新库且文件哈希不变。它证明进程中断保护；不宣称实际断电/硬件缓存故障验收。Windows的Node目录fsync不可用，文件本身明确flush；支持目录fsync的平台同步父目录。代价是中断后须维护恢复，不能自动猜测启用哪份副本。

本轮考察了 [npm/write-file-atomic](https://github.com/npm/write-file-atomic)（ISC，现有Node生态单文件原子写），其单文件rename不能替代SQLite主库/WAL/SHM的多文件恢复意图。项目现有短事务、VACUUM和文件flush能力足够，因此不新增依赖。实现只复用 [Node fs](https://nodejs.org/api/fs.html#fswritefilesyncfile-data-options) 与SQLite，单写入器、租约及owner重新装配保持原契约。十项统筹取舍见 [KNOWLEDGE_DECISIONS.md](KNOWLEDGE_DECISIONS.md)。

# 商品图片 OCR（1.0.17）

商品卡片“识别图片文字”读取本店有效平台图片来源，在主进程调用 Windows 原生中文 OCR，并显示逐图原始文字及图片预览。缓存以引擎和实际分块哈希为键，来源或工作区变化后拒绝晚到结果；退出时取消识别。Windows PowerShell 5 与中文识别语言包为运行环境要求，缺失时明确失败。

“开始学习”的估算阶段复用 OCR 缓存；正式视觉请求同时包含原图片及不可信 OCR 提示，由视觉模型判断文字与商品信息。辅助文字超出预算时明确提示并省略辅助提示，原图和缓存保留。识别完成不等于学习完成，学习结果仍为待审核知识。没有增加自动发布或买家发送能力。

批量托管学习在 `submitted` 检查点之前等待至少 13 秒间隔，本机模型不额外限速；暂停、取消和账号退出可取消等待，等待中的片段仍为未提交。此节奏不保证高于或替代服务端另设的更严格限制。实际模型名称和视觉授权由当前已鉴权账号决定。

收到的模型响应支持完整 JSON 代码块及原提示允许的空数组，不拼补截断 JSON。文字答案与图片依据仍逐条核对；图片答案如果只是所引文字的片段，保存完整引文（包括编号和否定词），再按原图片/位置和答案等于引文的规则校验；不能借此添加引文之外的内容。失败已收响应的任务可点“重新生成本片段（会计费）”，对应原 `knowledge/pipeline` 中受限 `retry-received` 动作：先归档本片段原响应/错误，只重做当前索引并保留已完成草稿。未知提交、已取消、已完成和其他店铺任务均不可借此重试；未知结果仍走单独的明确核对入口。

模型不负责分配资料身份：单来源调用如果漏回 sourceId，主进程只补为当前计划已验证的唯一来源；显式错误 ID、null 或其他类型仍拒绝，不猜测商品、店铺或事实。响应解析新增固定依赖 jsonrepair 3.15.0（ISC），先尝试严格 JSON.parse；仅在严格解析失败时尝试库修复，并逐字符限制为字符串外最多删除两个多余的 `}`，不插入任何字符、改变字符串或补全截断结果。修复后仍走原严格结构及依据校验，原响应和修复文本另存元数据、计入任务 syntaxRepairs。完整许可证保留在根第三方声明。
