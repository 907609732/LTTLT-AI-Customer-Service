# AI 辅助中心维护说明

本轮恢复 Figma UX26～UX32 的300px独立侧边浮窗。主界面保持原结构，辅助功能仍归属 auxiliary 模块，跨进程操作通过 shared 契约及受信 IPC。

## 产品约束

- 辅助中心为单例，可自由拖动或吸附灵兔主窗口；置顶与吸附分开控制。
- 最小化继续聚合与提醒；确认关闭停止辅助中心自身任务，不关闭店铺连接、不改变 AI 开关、不批准任何候选回复。
- 咨询与预警只使用已采集会话和真实状态；本机客服工单与平台工单分开标注来源。
- 手动发送复用原发送链路，未确认送达不自动重发，草稿按工作区、店铺和会话隔离。
- 纠错须绑定保留中的原买家问题和有效质检版本，确认后保存为本店知识，不发送纠错答案。
- 清除已回复列表只影响展示，不删除聊天归档；有新消息时再次显示。

## 平台后台采集边界

仅针对拼多多、抖店，读取登录后台的可见业务数据。后台页独立于聊天页面，不读取其他软件凭据，不调用臆造的私有 HTTP 接口。页面来源、店铺身份和空列表均须有验证证据；未知、未登录、读取失败不能返回成功的零条。

平台事项应保留来源、原状态、可用的金额/截止时间及上次同步时间。失败保留旧数据并显示已过期；账号或工作区切换后不得继续展示旧账号事项。刷新默认每60秒串行执行，避免后台页面并发争用。用户在原平台页面处理退款、举证及平台工单，侧栏不代提交这些操作。

抖店外部客户端无法复用后台登录时，可由用户首次登录隔离商家后台，核对为同一店铺后才采集。未完成实店核对的平台适配器必须如实说明，测试夹具成功不等于正式接通。

## 验证与交付

遵守 AGENTS 的增量验证规则：仅执行辅助中心组件、窗口/IPC、后台采集与直接依赖链路的相关检查。隔离模拟店铺用于发送验收，实店仅做只读核对，不向真实买家发送测试消息。常规开发不运行全量检查，不打包 Release。本轮代码先留本机验收，公开发布与部署不在范围内。

当前实际验证状态见[源码验收交接](HANDOFF.md)与[浏览器专项](ASSIST_BROWSER.md)；已完成实施计划可从Git历史恢复，后续交接须明确仍未完成的实店验证。

## 浏览器问题与当前范围

抖店按用户最新要求暂不处理。拼多多已实现非空售后及工单串行分页。实店待商家处理售后当前为零，非空字段用待买家处理2条只读核对；完整多页聚合通过原生隔离检查，不能据此宣称所有生产数据场景均已验收。浏览器对比、内核升级、页面复用与专项验证记录见 [ASSIST_BROWSER.md](ASSIST_BROWSER.md)。
