# 内置通用客服话术

## 使用

左侧栏底部「快捷回复」打开 80 条内置话术，按 10 个场景筛选，或搜索问题、场景与回复。每条有常见问法和可展开的适用条件。点击「复制话术」只写剪贴板，不填入平台输入框，不发送；复制失败会明确提示，也可选中文字手动复制。

正式回复与训练场都使用同一模型上下文准备入口：以本轮对话中最后一条买家文字召回最多 3 条表达参考，不整库塞入模型。最新买家消息若为图片或没有文字匹配，则不添加参考，也不沿用其他会话或上一轮的匹配。检索仅使用最新文字的末尾最多 2000 字符，实际聊天原文不因检索而截断。该匹配是相邻双字和触发语的文字相似度，不是语义意图分类，也不输出置信度。

日志 → AI 上下文调试 → 正式请求，可查看 `[通用客服表达参考]` 及本轮实际加入的示例、使用条件和边界。未命中不添加该块；不能用打开话术弹窗证明某轮请求已引用。

## 事实与发送约束

- 话术只提供沟通表达，不能证明商品规格、适配、库存、订单、物流、价格、退换资格、运费或退款进度。
- 本店业务规则、可靠资料和真实操作结果优先。明确答案已经存在时，不机械追问或用通用话术替代答案。
- 没有实际执行证据不得声称已经查询、登记、退款、提交、补发、联系物流或转接人工。
- 参考表达只改变上下文，不改变模型配置、店铺 AI 开关、限流、上下文压缩或逐条发送确认门。
- 不因内置库而新增模型请求。只有已有 16K/8K 机制确实触发时才执行原有摘要调用。
- 原文候选、原始 FAQ、意图规则、店铺标识、联系方式及源服务器信息均未导入软件。

## 来源与维护

`src/shared/customer-service/phrases.json` 来自用户要求整理的独立通用话术包中的 80 条人工编辑改写。它们参考了数据中沟通场景，不是逐条原文复制，没有每条改写对应某一条原始记录的映射。不要宣称已把 153 万条原始问答接入软件，也不能用本库声称来源数据已获授权。

`shared/customer-service/library.ts` 在启动时用 Zod 校验来源类型、字段、禁止自动发送标记和长度，提供浏览和有界文字召回；主进程与界面共用一份静态库。禁止将未审核候选、上传文件或商家自定义规则直接替换为系统参考。以后新增条目必须先核实通用性、去除个人信息与具体承诺，并保留 `context_required` 和 `avoid`。

`electron/generic-phrases.ts` 组合既有 `createContextCompressor`，在计量之前插入独立的系统约束与静态示例块；买家查询、原始 FAQ、其他店铺资料不会被升级成系统指令。压缩器保留系统块，因此参考及其 token 均参与真实预算和最终请求。系统与受保护内容超预算时继续拒绝，不删改规则来强行通过。

`workbench/services/generic-phrases.ts` 经 `shared/platform/clipboard.ts` 发起显式复制。新增 `DesktopApi.copyGenericPhrase(id)` / `app:copy-generic-phrase` 只接受已知内置 ID，由主进程选出文字。沿用应用主框架、可信 URL 与窗口归属验证；不开放剪贴板读取或任意内容写入，不开放自动发送。浏览器预览仅在用户点击后使用浏览器剪贴板能力；权限拒绝如实提示。

不增加业务持久化、IPC 任意文件访问、依赖、环境变量或 vendor 补丁。自定义话术编辑/导入与跨设备同步不在当前范围，当前只有随软件版本维护的内置库。

## 验证与运维

运行 `npm run check` 和 `npm run test:desktop`。单元覆盖实际 AiClient 正文与 trace 一致、店铺知识保留、用户原文不升级为系统指令、最新买家消息选择、无匹配不沿用、16K/8K 压缩、复制 ID 与失败呈现。桌面覆盖 80 条真实渲染、场景筛选、搜索与空态、错误 ID 拒绝、真实训练请求及不可信窗口拒绝；不自动改动系统剪贴板，也不向真实买家发送。

界面截图：`artifacts/desktop/generic-phrases.png`、`generic-phrases-search.png`。发布时重建渲染层与主进程，重启软件后生效。回退时恢复 `local-runtime.ts` 的原压缩器装配，并回退相关界面/IPC，不能删除用户本地业务数据。初始改动前的两个入口备份在 `artifacts/before-generic-phrases/`，不是完整版本管理快照。
