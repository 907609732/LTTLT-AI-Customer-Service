# 店铺 AI 开关记忆

用户于2026-11-16要求登录自动恢复上次退出时的AI设置。

## 使用与范围

沿用原店铺AI开关。从本版开始，每次明确开启/关闭都会记忆；记忆随共用的本机 `local-runtime` 业务目录按店铺保存，不再按账号或模型来源分目录（2026-11-17 共用工作区整合）。缺失、损坏或没有有效身份的记录保持关闭，不推测旧版退出历史，不自动开启新店。

普通启动或账号登录后，只为记住开启的店铺在后台执行既有打开流程。当前平台明确登录、连接就绪，并重新读取到匹配的店铺与客服身份后，通过原set-ai命令启动。未登录时等待验证，不用保存的旧身份或online标志冒充本次登录验证。失败不循环重试，用户可手动核对后开启。

状态复用店铺侧栏原状态位置及提示，不新增设置页。开关反映实际运行状态；恢复等待期间可取消。原审核/自动发送模式独立保留，不恢复旧候选、批准或待发送任务。

## 持久化与生命周期

复用StoreSendModes的主进程原子JSON写入模式，使用当前managed.dataDir中的独立store-ai-preferences.json，不修改发送模式文件。仅保存店铺标识及平台身份，不保存凭据或买家内容；不新增IPC或依赖。

显式关闭、全部关闭、主动关闭店铺和移除店铺取消恢复。退出、临时断线及托管故障停机不覆盖原意愿。写入失败不能阻止实际停止AI，且必须避免当前会话稍后再次自动开启。成功开启后若记忆写入失败，不得伪报已记忆。

模型来源/账号切换、注销、平台身份变化和退出使在途恢复失效，晚到结果不能重新开启。知识库清除/恢复的维护重建明确抑制本实例自动恢复，保持现有维护确认语义；下一次正常软件/账号会话仍可按持久偏好恢复。

## 复用取舍

现有StoreSendModes已经具有按账号目录保存及原子替换能力。也检索了[electron-store](https://github.com/sindresorhus/electron-store)：它支持原子写入，但当前为原生ESM且重复现有小型偏好存储能力，本次不引入该依赖或其源码。

## 验收边界

用临时目录、合成身份与受控异步任务验证开关记忆、隔离、损坏文件、延迟登录、失败及取消竞争。真实店铺恢复与真实模型发送需分开记录，不把合成测试当作平台已发出回复。
