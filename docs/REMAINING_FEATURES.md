## 业务设计

### 平台学习

现有学习页增加平台商品/平台聊天来源。主进程读取已验证店铺真实平台资料，持久化任务、范围、游标、候选和去重指纹。人工审核后保存为停用知识包，再显式启用；不能把当前本机历史误称主动全量采集。关闭/重启保留任务，未完成任务暂停，重启不自动续跑到其他账号。

### 事件、执行与批准

真实访客、未付款订单及客服状态只能来自平台provider。无消息访客不能由空本机归档推断；催付订单由可信事件绑定，规则不能写死另一笔订单。媒体、文字、催支付及转接分别展示准确目标和内容，一次批准只执行一项。执行前复核店铺、买家、页面、订单及客服；新消息、已付款、客服离线、停店或账号切换取消旧事项。

审批状态为待批准、执行中、已确认、失败、待核对、失效、取消。重启不恢复批准；不确定结果不可自动重发。图片/视频须验证资源大小/类型、目标买家及对应卖家媒体回显，不能以全页媒体数量增长判成功。真正未暴露能力的平台必须保留明确外部阻塞，不能用假事件或blocked提示冒充接通。

### 平台订单

订单与软件充值订单分开。看板提供平台订单页签，按店铺、北京时间日期及状态读取，记录已读页数、条数、平台总数、范围和最后成功时间。分页全成功并覆盖声明范围才称完整；失败保留旧结果但标注来源和过期，不发布部分完整。金额用整数分，实付合计和退款口径分开，不将实付合计称为净营收。复用PapaParse支持平台官方导出文件，导出附范围和完整性。

### 充值与服务

独立充值路由增加固定返回工作台、返回配置中心和现有窗口操作，不依赖历史返回。账本、套餐、订单加载分别保留错误；404服务未部署、401登录失效、商户缺配置、网络失败和订单冲突使用明确状态，去除IPC技术前缀。失败不能显示为成功空套餐。

服务端提供版本/计费能力与配置自检；复用受限会话和管理员加密设置，不向客户端下发商户密钥。真实商户测试需要实际商户配置。生产修复须先形成已验证、可回滚的服务产物与路由检查，未获得相应部署授权不修改生产数据。

## 统一验收矩阵

1. 新平台商品/聊天→候选持久化→完整退出重启→审核入库→启用后训练召回，验证来源与账号隔离。
2. 平台真实事实→单条待批准→实际执行证据；没有批准零写动作，错误目标/已付款/离线/过期全部阻止。
3. 订单分页与原平台已知总数相符；去重、金额整数分、日期口径、退款与部分失败清晰，官方文件导入同口径。
4. 充值直接路由返回/关闭可用；服务404、401、未配置和成功态可区分；签名付款只入账一次并显示真实账本。
5. 真商户/真实发送等外部验收需要对应已配置环境与用户逐条批准；缺条件不制造样本、不假称完成。
