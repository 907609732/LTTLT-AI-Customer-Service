# 当前Figma前端与desk-v1后端接线设计

## 目标与来源

将远程拼夕夕分支最新提交8b50c462b03fbf4409a1066093c43092ede0c1e6的本地后端接入当前v0.2.3 Electron+React前端。沿用用户已确认的现有客户端与服务复用方向，保留Figma图层、32来源页面、1440×900基准、自适应及300宽辅助侧栏。

## 方案与约束

采用同一个Electron主进程装配现有后端模块，前端通过有类型、白名单且验证来源的IPC调用；不启动第二套客服台界面。两程序HTTP中转会增加进程与状态一致性负担，替换为desk-v1自带界面不符合保留Figma要求，因此不采用。

合并后保留desk-v1原始模块和测试，新增可复用服务装配入口；不直接require会自行创建窗口和启动程序的desk-v1/src/main/index.js。继续使用客户端现有Electron版本，补充后端实际需要的zod依赖和打包文件。

## 接线范围

1. 店铺：首页/添加店铺/店铺列表使用真实注册表，支持现有pdd-web及doudian-client；其它平台明确未支持。显示真实打开、离线、等待客户端、失败状态和可读错误；新店AI关闭。
2. 平台页面：复用WebContentsView和平台适配器，登录采集页面与Figma配置页面分开呈现。优先将平台页置于受控独立店铺窗口，避免原生View遮挡React菜单、弹窗和配置页；窗口关闭及时清理监控，登录分区隔离。
3. 状态：主/辅助窗口共享真实选中店铺、消息和引擎状态；订阅后端事件，初次载入取快照，重载可恢复列表与历史。界面不再把设计里的示例昵称和消息作为真实数据。
4. 回复：把采集消息映射到辅助中心会话及历史，选择会话后启用真实回复。手动发送必须明确指定店铺和会话，由主进程校验并调用适配器，失败保留输入；无会话时禁止发送。AI开关、暂停/恢复、批量操作调用现有引擎并反馈逐店结果。
5. 配置：模型规则/端点/模型、转人工关键词及现有后端支持的设置映射到真实配置和加密密钥存储。密钥不回传明文、不写React持久化和日志。现有设计没有完整端点设置时，增加与现有样式一致的必要设置弹窗。
6. 数据：配置、店铺、密钥和会话存档使用当前软件独立userData目录；不擅自导入或覆盖desk-v1已有用户数据。真实配置保存成功后才推进已保存草稿。
7. 未具备能力：欢迎语主动发送、定时调度、图片识别服务、意图知识库、工单/质检/订单/算力等缺少后端契约的部分明确提示未接入；不返回演示成功。具体映射以现有模块可执行能力为准，交付列出矩阵。

## 启动与安全

AI自动回复每次启动默认关闭，用户显式开启后才运行；测试不会自动打开真实店铺、调用真实AI或发送买家消息。保留sandbox/contextIsolation和受限来源IPC，第三方平台页面不能调用管理接口。抖店桥接沿用回环监听与方法白名单。程序退出清理引擎、监控、店铺窗口和桥接服务。

## 验证与交付

先运行前后端原有检查；增加跨层集成测试覆盖真实文件持久化、双窗口状态、错误传播、消息路由、发送目标及启动关闭AI。外部平台/AI依赖用受控适配器和本地fixture验证，不能冒充真实平台验收。

保留当前视觉与响应式回归，实际Electron验证添加店铺、保存配置、重启回读、消息显示及手动回复测试链路。正式构建和打包仅在GitHub云端进行，下载同次产物校验后本机运行。真平台登录和向真实买家发送需要用户参与，交付明确区分本地集成测试与真平台结果。

## 实施者可决定事项

服务装配文件命名、事件快照类型、状态订阅实现和必要新增对话框采用当前React/CSS体系；优先复用现有模块，不新增HTTP服务，不另造平台采集方案。

## 复核补充

现有后端暂停/停止只阻止后续轮询，在途AI请求或延迟发送仍可能完成。集成时增加运行代次/取消检查，发送前再次核验店铺与会话是否仍允许回复；关闭AI、暂停和退出后不继续发送。用受控在途请求和延时测试验证，不触发真实买家消息。
