## 1. 用户已确定的需求

- 为本软件建立网站，开发者可以及时查看开发进度和策划文档。
- 任何人拿到链接均可阅读，无需登录。
- 最新选择是继续在代码仓库维护，网站自动同步；此前网站内编辑、分配任务的选择已被替代。
- 公众网站遵守用户既定的同一自定义域名双端部署：大陆阿里云，境外 GPT Sites；不把客户端安装包放在 3 Mbps 服务器。

本文件中其余页面结构、时间间隔、技术细节均为 Codex 根据现有项目提出的建议，不代表用户逐项指定。

## 2. 目标、范围及不做的内容

首期目标是打开网站即可知道现在做什么、哪些事项阻塞或待验收、规划依据在哪里、什么版本实际交付。信息以经确认的仓库记录为准，包含来源版本与核验时间。

首期包含四个入口：进度总览、开发任务、策划文档、版本记录。支持关键词、模块及阶段筛选，任务和策划互相链接，支持手机浏览和可分享的详情地址。

不建设网站账号、在线编辑器、任务分配后台、评论、即时聊天或通知系统。网站不是客服软件运行监控，不读取真实店铺会话、客户资料、账单、模型 Key、数据库或本机浏览器登录态。公开网站不自动等于把整个 docs 目录复制发布。

## 4. 仓库内容与事实规则

建议独立 `progress-site/` 放网站构建、主题和同步代码；`docs/public/` 放公开策划与说明；`docs/progress/` 放结构化任务和里程碑；显式清单列出可发布内容。新增命名最终由实施计划确定，保持职责分开，不影响桌面 src/electron/server 业务。

现有资料用于人工核对初始内容：`docs/HANDOFF.md`、`docs/REMAINING_FEATURES.md`、`docs/DECISIONS.md`、`docs/superpowers/specs/` 和发布说明。HANDOFF 不是结构化实时接口；旧计划中的勾选、版本号及模型总结不能直接转成事实状态。初始内容按当前核验结果编写公开摘要，不整包搬运内部交接。

任务必填：稳定 ID、标题、模块、目标、阶段、下一步、验收条件、最后核验时间、关联策划和公开证据。负责人未知时显示未登记，不编造人名或日期。阻塞事项写明原因和解除条件。

阶段：规划中、开发中、待验收、已验收。阻塞作为独立标记，取消的工作单独归档。源码合并、验证范围、软件 Release、生产部署分别记录，未知或未核验显示未知。无真实数据时不显示虚构完成率，不依据提交数量计算进度。

策划文档标记草案、已确认、已替代；显示修订时间、适用模块、关联任务；旧稿链接当前稿。仅用户已确认的设计才标为已确认。

维护规则：开发者在同一个 PR 更新公开进度或策划，main 合并才触发公开内容同步；分支和本机未提交修改不会凭空出现。涉及公开任务而未更新记录的 PR 通过检查提示维护，不让模型自动猜测完成状态。具体任务记录由开发者或执行任务的代理显式维护。

## 5. 信息结构与交互

- 进度总览：当前里程碑、正在开发、阻塞、待验收、近期变动；提供进入任务和相关策划的入口。
- 开发任务：搜索、模块与阶段筛选，条件放入 URL；列表显示名称、阶段、模块、负责人和核验时间；详情展示目标、下一步、验收条件、阻塞及证据。
- 策划文档：目录、阅读页、章节导航和搜索；展示文档状态及关联任务；支持稳定文档 ID 链接，新增文档不要求重建前端路由。
- 版本记录：公开软件发布与网站内容版本分别呈现，链接真实 tag、PR 和可公开的测试/部署摘要；不存在的发布不显示为已上线。

检查更新时不打断阅读。发现新内容提示“有更新，点击载入”，用户操作后原子替换整个内容版本并尽量保留阅读位置与筛选。检查失败保留旧版本并显示最后成功时间，不清空内容，也不假称服务端发布失败。

无匹配提供清除筛选；未登记、未核验及未收录有明确文字。颜色不作为唯一状态表达，键盘可用。

## 6. 自动同步与地区部署

需要区分网站程序版本和公开内容版本。不能假设普通 Git 推送就会自动触发 GPT Sites 发布，也不能把仅浏览器打开时更新称为后台同步。

推荐采用同一前端构建双端部署，日常内容独立更新：

1. main 的公开内容或相关实现变更触发 GitHub Actions，校验结构、关联链接、公开清单和敏感内容，生成只包含允许字段的版本化内容包及 manifest。
2. 内容包包含任务、策划正文、搜索所需数据、内容 source_commit、schema_version、文件哈希和 generated_at。策划正文经成熟 Markdown 解析器生成并使用允许标签规则处理，不信任任意 HTML、脚本或远程资源。
3. 使用 GitHub 自带的短期 GITHUB_TOKEN 将通过校验的公开产物写到专用发布分支，避免把服务器私钥或长期云密钥复制进聊天或仓库。只允许受信任 main 的工作流写入，外部 PR 不获取部署权限。
4. 大陆服务器上的受限内容更新服务每 60 秒检查该公开发布分支，从同一受信任仓库拉取到新的 release 目录；校验 schema、SHA/哈希、文件数量和大小，只处理公开内容数据，不执行远端脚本；通过后原子切 current。服务账户无权修改客服数据库、其他站点或系统目录。并发与旧构建不得覆盖较新版本。
5. 两端页面从同一个只读 HTTPS 内容源读取 manifest 和相应不可变内容包；只按完整版本切换，不混用新任务与旧策划。该源可由大陆现有 Nginx 的独立路径提供，无需新增业务数据库。最终主机名和路径在部署前检查冲突后确定。
6. 前端启动及恢复可见时检查版本，正常可见时每 60 秒轻量条件请求；隐藏时暂停。manifest 短缓存，正文按哈希长缓存并 gzip；不跨源传 cookie 或认证数据。
7. 网站外壳功能变更仍须同次构建、分别发布并验收大陆和 GPT Sites；普通内容变更走共享内容源，不要求每次重新发布外壳。若出现 schema 不兼容，保留旧版本并提示需更新网站，不渲染混合版本。

“实时”的首期定义为：main 合并后自动进入构建与同步，正常情况下构建完成后约 1～2 分钟内两端检查到新内容，实际耗时在验收中测量，不能先承诺秒级。网站显示内容核验时间、内容 SHA、最后成功加载时间；网站程序版本另列。

共享内容源或 GitHub 临时不可用时显示最后已验证的完整版本及过期提示，恢复后继续更新。初始构建可附一份明确时间与 SHA 的最后已验证内容作为离线后备；不能把后备称为实时。首次加载尚未成功且无完整后备时展示错误与重试。

用户既定双端与 HTTPS 规则继续适用。建议评估 `progress.lttlt.top`，尚未分配、未写 DNS；本机 DNS 返回代理地址，不能据此判断域名是否空闲。上线前使用权威 DNS/公共解析核对记录、IPv6、地区能力、TLS 和旧域名行为。大陆先验收再切 DNS，保留回滚；证书优先沿用受限 acme CNAME 与共用锁，不新增长期 AccessKey。共享内容域名两地区均须验证 HTTPS、CORS、缓存及真实读取同一 SHA。

## 8. 环境事实、验证与实施边界

已核对：Windows Node v24.18.0、npm 11.16.0、Git、本机 DeepSeek headless 入口；主项目 Vue3/TypeScript/Vite，已有相关源文档。DeepSeek 只读策划任务退出 0，final.reason.kind=completed；Codex 独立核对了文档和三个 workflow 的触发范围，当前没有进度网站发布流程。

尚未验证：服务器资源与受限部署账户、现有 GitHub Actions 写分支权限、无人值守服务器拉取、共享内容跨地区访问、GPT Sites 首次发布、自定义域名 DNS/TLS。上述项目是实施与发布验收条件，不是已成功能力。

验收必须覆盖：

- 从真实但可公开的当前资料建立首批任务与策划摘要，并逐项保留事实范围。
- 结构化记录和关联链接校验；禁止清单外文件、私有附件、凭据及内部路径进入公开包。
- 本机最小构建、任务筛选/详情、文档阅读/搜索/锚点、手机宽度与键盘交互。
- 提交一个公开记录变更并合并后，无本机人工干预，由正常工作流和服务器更新服务使两端读取同一新 SHA；记录延时与内容一致性。
- 模拟构建失败、更新源不可用、半包、旧版本晚到、schema 不兼容；应保留上一完整版本并如实提示。
- 大陆/境外逐站检查、TLS 实际续期测试、DNS 与回滚；任何未通过项必须列为未完成，不能用安装成功代替。

在用户确认本设计后编写实施计划；实现按策划→UX→UI→开发与整合的顺序开展。现阶段未建立网站、未安装网站依赖、未修改 DNS、未部署生产。
