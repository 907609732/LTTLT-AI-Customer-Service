# AI 配置接口设计（待确认）

## 目标与范围

让本机 AI 无需操作界面即可读取、预览和修改软件的日常配置。用户已选择 MCP + CLI：第一期开放全局回复间隔、按店铺的欢迎语和识图开关。模型参数、凭据和其他业务配置留待后续明确范围。

## 方案选择

- 仅扩展 MCP：接入成本最低，但无法方便地通过普通命令行脚本使用。
- MCP + CLI 共用服务（用户选择）：扩展现有 agent gateway/service，CLI 复用同一认证 HTTP 客户端，配置校验与保存只有一份。
- 独立配置服务或直接编辑数据文件：增加生命周期与状态同步成本，不采用。

复用已安装的官方 @modelcontextprotocol/server 2.4.0、Zod 及现有主进程配置保存逻辑；不新增配置数据库、不自行实现 MCP 协议。官方来源：https://github.com/modelcontextprotocol/typescript-sdk 。

## 接口与行为

- MCP 增加配置字段发现、读取、修改预览、提交工具；工具名称及详细字段由实现计划确定。
- CLI 提供对应的 schema/get/preview/apply 操作，JSON 输入输出、明确退出码、帮助及调用示例；复用运行中软件生成的实例连接文件。
- 每次只提交一个配置分组，店铺设置必须明确 storeId；不提供隐式跨店批量写入。
- 返回字段类型、合法范围、当前值和版本；预览返回修改前后差异，不持久化。
- 提交携带当前 workspaceId、预期配置版本及 requestId。主进程检查并发变更，拒绝覆盖较新的配置；复用现有工作区租约和请求去重保护。
- 保存沿用现有业务命令及持久化路径，回读实际保存值，不把预览或请求受理冒充保存成功。
- 不通过这些配置工具修改模型密钥、登录状态、AI 启停或发送审批，不开放任意命令、文件或数据库访问。识图开关不保证模型支持图片，保留原能力检查。
- 保留现有 MCP 工具和客户端兼容性。网络结果未知时先读取当前配置核查，不自动换 requestId 重试。

## 验收

使用临时数据覆盖三类配置的读取、预览不落盘、保存回读、非法字段/范围、店铺及工作区隔离、版本冲突和重复请求。通过真实标准 MCP 客户端及 CLI 子进程验证端到端调用。构建及相关类型/静态检查通过后，按项目要求升一次 patch 版本，并核实、重启本项目源码供查看；不修改现有真实配置进行测试，不公开发布安装包或部署服务端。
