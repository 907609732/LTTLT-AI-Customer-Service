# 可配置图片识别模型设计

> 当前状态（2026-11-19）：本机独立视觉领域和公共装配已实现并纳入代码；托管视觉渠道/管理员验证仍在独立 server 分支。本文保留最初设计依据，实际接口与限制以 `docs/LOCAL_VISION_MODEL.md` 和 `docs/HANDOFF.md` 为准。

## 意图

用户希望试用 DeepSeek 多模态，并能为图片识别选择合适的模型接口。本机自带 Key 模式和托管服务都需要可配置视觉模型，同时保持文字模型独立。

## 目标

- 本机设置提供独立的图片识别模型配置：服务商预设或自定义 OpenAI 兼容 API 地址、模型名和 API Key。
- 本机视觉配置默认沿用文字模型；用户切到独立配置后可在不改变文字模型的情况下试用 DeepSeek 等视觉模型。
- API Key 只在主进程加密保存；快照、日志和托管客户端均不包含密钥原文。
- 托管管理员可在已接入渠道中选择图片请求使用的模型；客户端不能指定或绕过该路由。
- 托管视觉候选必须来自当前启用、连接测试通过、图片能力验证通过且包含在当前试用授权范围内的模型渠道。
- 文本连通、模型列表或名称匹配不能单独证明支持图片；图片能力通过明确的实际图文请求验证。
- 配置、授权或渠道状态变化使视觉验证失效时，图片请求在预留额度前明确失败，不静默切换模型。
- 保持现有文字模型、计费和历史策略行为；不新增模型 SDK 或其他运行时依赖。

## 非目标

- 重做通用文字/图片模型路由器或允许桌面用户直接指定托管上游模型。
- 从客户端读取或下发托管渠道密钥。
- 自动探测全部模型能力，或仅根据模型名称推断视觉支持。
- 自动改写已保存的托管额度、授权范围或用户账号偏好。
- 修改买家消息发送确认门、店铺 AI 状态或生产部署流程。

## 约束

- 项目使用 Vue 3、Electron、TypeScript；服务端使用 Go 和现有 New API 模型渠道。
- 本机模型 Key 当前由 Electron 主进程使用系统加密保存；IPC 命令与快照采用白名单契约。
- 本机视觉能力策略位于 `electron/model-capabilities.ts`；现有设置使用兼容 API、模型列表读取和训练流程。
- 托管视觉路由目前由 `server/overlay/lingtuhost/vision.go` 固定为 `qwen3-vl-plus`；路由和模型范围位于 `model_policy.go`，管理页面位于 `server/overlay/web/src/features/lingtu`。
- 托管服务器拥有模型接口和密钥，密钥不得进入桌面客户端。
- 图片验证只能由用户或管理员显式触发；使用固定、无客户信息的测试图片，可能产生上游 API 费用。

## 方案

1. **所有请求共用单一模型配置**：实现最少，但试用 DeepSeek 视觉会同时改变文字模型，也无法由托管端独立选视觉上游。
2. **本机独立视觉接口 + 托管端选择已验证渠道（选定）**：文字模型保持不动；本机可自带 Key 验证自己的视觉接口；托管管理员从已配置渠道选择路由。改动局限在现有模型设置、模型渠道和策略上，密钥及授权边界清楚。
3. **通用多模型路由器**：在桌面和服务端同时开放任意文本/图片模型及路由规则，灵活度最高，但会扩大计费、授权、凭证和用户选择复杂度，超出本次试接视觉模型的目标。

## 设计

### 本机模式

- 在现有模型设置增加“图片识别模型”区块，模式为“沿用文字模型”或“单独配置”。旧配置缺少该字段时解释为沿用，不影响现有用户。
- 独立配置包含服务商预设、自定义兼容 API 地址、模型标识和 API Key；DeepSeek 使用官方 OpenAI 兼容端点与其当前支持图片的模型 ID。自定义 API Key 走新的白名单命令进入 Electron 主进程，并使用现有系统安全存储能力保存。
- API Key 只写入，不从快照回显；快照只返回 `apiKeyConfigured`。更新文本配置不得覆盖视觉配置，反之亦然。
- 对当前有效视觉配置分别显示普通连接验证和图片能力验证。连接测试只检查端点可用；“验证图片识别”由用户显式触发真实图文请求，只有成功后标记视觉能力已验证。配置改变即清除验证状态。
- 图片知识处理调用独立视觉模型；文字训练、接待回复和摘要仍使用原文字模型。模型不支持图片、连接失败或视觉验证过期时显示明确错误，不静默回退到其他模型。

### 托管模式

- 托管模型渠道管理支持对某条已配置渠道执行显式“验证图片能力”。验证使用服务端固定测试图片和短提示，不把密钥、图片数据或内部通道标识返回给桌面端。成功状态绑定渠道配置摘要/修订；编辑密钥、端点、模型或禁用渠道会使其失效。
- 试用策略增加独立的视觉路由模型字段。管理员只可选择启用、连接测试成功、视觉验证有效且被当前授权模型范围包含的渠道模型。
- 已配置的 Qwen3-VL 路由保持为兼容默认；没有新视觉路由字段的旧策略继续按原 Qwen 语义处理，除非渠道不再就绪，此时闭锁并提示管理员修复。
- 选定视觉模型不在 `selected` 授权范围时阻止保存并提示先加入授权；不自动扩展授权范围。`all` 范围仍遵从现有授权规则。
- 图片请求仍由服务端决定上游模型并记录实际模型用量/成本；无有效视觉路由时在额度预留前返回明确不可用错误，不静默使用文字模型。
- 客户端能力投影只表示存在可用图片路由，不暴露服务端密钥或上游地址。

### 交互状态

- 本机：沿用当前模型 / 独立配置；API 连接未验证 / 连接已验证 / 连接失败；视觉未验证 / 视觉已验证 / 验证失败 / 配置变更后需重验。
- 托管：已选路由、视觉验证过期、模型未获授权、无可用候选等状态均在管理页面显示原因和下一步。保存失败不改变现存路由。
- API Key 输入框不填回旧密钥；已保存时显示“已配置”，清除密钥需显式操作并确认。

## 主要涉及范围

- 本机后端持久化、模型请求入口、能力快照及命令契约：`electron/local-runtime.ts`、模型服务与配置、`electron/model-capabilities.ts`、`src/shared/contracts/backend.ts`。
- 本机模型设置交互及说明：`src/modules/settings`、相关样式和 `docs/LOCAL_INTEGRATION.md`。
- 托管渠道视觉验证、路由策略持久化/兼容、能力投影：`server/overlay/lingtuhost`。
- 托管管理员渠道和试用策略页面：`server/overlay/web/src/features/lingtu`。
- 管理文档、服务交接和策略决策记录。

## 验收标准

- 本机文字模型保持不变时，可单独配置 DeepSeek 图片模型接口、模型名和 Key；图片学习请求实际携带图片到该配置的视觉模型。
- 本机 Key 既不出现在任何快照或日志中，也不随着托管模式登录传到服务器。
- 自定义配置的普通连接成功不能显示视觉验证成功；实际图片验证通过才开放图片能力，配置变更会要求重新验证。
- 托管管理员只能选有效验证且在授权范围内的视觉模型；用户请求不得覆盖所选模型。
- 无视觉路由、验证过期、渠道禁用或授权不足时，托管图片请求在预留额度前失败；不落到文字模型。
- 旧客户端配置和旧托管策略保持现有行为；数据库/配置迁移不修改已发放额度及旧授权。
- 文字成本、视觉成本和计费模型都依据实际路由记录；界面准确展示当次使用的配置与失败原因。
- 通过针对性桌面和服务端验证；不调用真实买家资料，不部署生产，不发布安装包。
