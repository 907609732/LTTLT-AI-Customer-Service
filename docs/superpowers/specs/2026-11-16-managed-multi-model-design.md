# 服务端多模型选择设计

## 已确认需求

管理后台支持“全部模型”或“指定多个模型”，保留默认模型。账号指定模型只是默认偏好，账号仍可选择允许范围内的其他模型。

## 方案与取舍

采用现有 New API 托管连接目录、Gin/GORM 和原生 React 表单，扩展现有策略和接口；无需另建模型网关。只修改下拉框不足以满足请求选择与权限校验；引入第二套网关则重复现有渠道和凭据管理。

## 行为

- 全部模型指后台托管目录中已启用且实际可用的连接，不代表未配置服务商或互联网所有模型。新启用的可用连接自动进入列表。
- 指定模型使用多选，至少选择一个；全局默认模型必须属于允许范围。
- 账号指定模型为默认偏好，仅在允许且可用时生效，否则使用全局默认；若全局默认不可用则使用允许范围内排序稳定的首个可用模型。无可用模型时明确报错。
- 配置接口返回允许且可用的模型标识和名称，不返回渠道地址或凭据。聊天请求可携带模型标识；缺省时使用有效默认，显式选择不允许或不可用的模型时报错，不静默替换。
- 服务端统一校验范围再进入既有渠道绑定、调用计数与结算流程。请求摘要包含所选模型，避免同一请求 ID 跨模型错误复用结果。
- 旧策略未设置范围时保持既有单模型行为；管理员保存新范围后启用多模型。旧客户端不传模型仍可调用默认模型。
- 引用中的连接不得直接删除，需先调整范围和默认值。禁用或连接失效后，不再向客户端提供该模型。

## 界面及边界

试用设置增加“可用模型范围：全部 / 指定模型”，指定时显示多选列表，保留默认模型选择。该范围约束当前托管模型调用，额度规则不变。此次完成服务端和管理后台以及客户端接口契约；如桌面端尚无模型选择入口，明确记录，不把接口可选宣称为桌面交互已验收。

## 验证与交付

验证策略保存、全部动态扩展、多选过滤、默认回退、旧策略兼容、越权拒绝、模型失效及同请求 ID 的模型冲突，并检查受影响后台界面。保留工作区其他未提交改动；仅本机测试，不操作生产数据库、密钥或部署。
