# 灵兔账号与托管模型服务设计

日期：2026-11-09。状态：用户已确认功能范围；环境与上游契约已核对；具体界面待核对。

## 已确认范围

- 面向任何人开放注册，微信、钉钉首批同时接入，邮箱作为备用。用户确认两种开放平台应用均已拥有。
- 每个新账号自动获得 20 次试用，有效期 7 天。后台可修改默认规则及单个账号的授权；同一已绑定身份不重复赠送。
- DeepSeek、千问的上游 Key 只保存在服务端；客户端登录后按账号权限直接调用，不再要求用户填写模型 Key。
- 登录自认证完成起绝对有效 30 天；期间自动刷新短期令牌，正常更新不退出；满 30 天重新认证。后台可提前撤销。
- 管理后台覆盖账号、模型与 Key、默认试用规则、用户授权、用量记录、停用和登录会话撤销。
- 此期不包含收费、充值、订阅支付、多租户企业团队或远程控制本机店铺。

## 环境事实与实现路线

客户端以已发布 v0.4.4 的提交 `6792f03cf4d8f208cd7113802b91358f911ffe11` 为基线，Electron + React + TypeScript，现有本地 backend 已支持店铺、模型直连、系统加密存储及软件内更新。

当前阿里云 SSH 别名 `aliyun-erp` 已只读核实：Linux x86_64、有 Docker/Nginx；约 1607 MiB 内存，检查时可用约 391 MiB；已有数据库、网站及业务容器。新增业务必须独立目录、容器和监听端口，不能覆盖或重启其他项目。

上游采用 New API 当前发布 `v1.0.0-rc.49`，固定提交 `48a6c87f9e7757fdc58e5be9bcb4f8281ad0dfd0`。已读其 `docs/authentication.md`：原生已有 15 分钟 Access Token、最长 30 天且可撤销的 Session、刷新轮换、临时 AuthFlow 和后台二次验证。通用 OAuth 驱动仅 POST 换取令牌，不能直接当作微信网站登录适配器。

选择扩展 New API 单进程方案，复用其账户、渠道、管理界面和模型协议；新增客户端认证、微信/钉钉适配器和试用次数账本。独立 SQLite 持久卷，第一版不再添加 Casdoor、Redis、PostgreSQL 或 Node 常驻服务。现有业务数据库不共用。

考虑过的另一条路线是未修改 New API + 独立身份平台/业务中间层；它便于分开升级，但增加常驻进程、数据库与跨服务授权同步。在本机服务器当前资源下，优先单进程扩展。完全自研模型网关不符合本项目复用成熟组件的方向。

客户端仓库保存固定上游版本、可重放补丁与构建步骤；构建在 GitHub 完成，构建结果须能追溯到上游提交和补丁。第三方源代码保留其许可，不擅自改成客户端自身的许可版本。

## 账号及第三方身份

- 内部用户 ID 是权限、会话、试用和用量的唯一归属，不采用昵称或前端提交的 userId 作为授权依据。
- 外部身份绑定用 `(provider, application_id, verified_subject)` 唯一索引。微信优先已验证的 UnionID，缺失时使用应用内 OpenID；钉钉使用接口返回的稳定 UnionID/主体标识；邮箱必须验证所有权。
- 昵称、头像、未经验证的邮箱不触发自动合并。绑定另一登录方式要求已登录且重新验证该外部身份；已绑定身份不能被另一个账号接管。
- 一个规范账号只领取一次注册试用。换设备、重新登录、升级软件、绑定新方式均不补发。不同且未绑定的身份不能被可靠认定为同一自然人，不宣称解决所有多账号注册；使用服务端限速与全站试用上限控制消耗。
- 公共注册不能写入管理员角色、账号启用策略、余额或试用次数。初始管理员通过私有初始化流程创建，不能由首个公共注册者获得。

## 客户端登录流程

1. Electron 主进程向 `/api/client/auth/device/authorize` 建立短期登录流程，获得随机 device_code、用户确认码、验证地址、到期时间和轮询间隔。device_code 仅在主进程内存中保存，服务端仅保存摘要。
2. 软件显示确认码，并通过系统浏览器打开固定自有验证域名。地址只含用户确认码，不含登录令牌或上游 Key。
3. 浏览器提供微信、钉钉、邮箱入口，使用服务端生成且一次性的 OAuth state。第三方回调必须是后台登记的固定 HTTPS 地址。
4. 认证完成后，页面显示将登录的灵兔账号与确认码，用户确认关联该客户端。确认码与软件显示一致，避免静默把错误账号登录到另一台设备。
5. 主进程按服务端规定的间隔兑换 device_code，流程只能原子完成一次；成功后得到客户端专用短期 Access Token 与刷新令牌。
6. Access Token 仅在主进程内存；刷新令牌用 Electron safeStorage 加密保存在稳定 userData 路径，绑定服务端 origin、用户 ID、会话 ID 与绝对到期时间。加密不可用时不得明文或 base64 持久化。

此流程采用 OAuth Device Authorization 的设备码模式，避免给微信/钉钉登记动态 localhost 回调端口，也不把桌面客户端当成持有 client_secret 的机密客户端。实现需遵循 RFC 8628 的到期、轮询限速、拒绝授权与单次兑换语义。

微信网站应用与钉钉登录应用各用官方授权、换令牌和用户信息接口，服务端做专用适配；AppSecret 和厂商 Access Token 都不能返回桌面、出现在 URL 日志或错误信息中。邮箱备用采用验证过的邮箱注册/登录及上游现有恢复机制，不伪造投递成功。

## 会话与权限边界

- 客户端令牌使用独立 audience/purpose，只能访问 `/api/client/*`，不能访问 New API 管理、渠道或用户 API Token 管理端点。
- 客户端会话复用原生会话撤销与版本控制机制，但不能把网页后台的刷新 Cookie 直接复制为桌面凭据。浏览器后台仍保留 HttpOnly/Secure Cookie；桌面刷新走专用受限接口。
- 刷新凭据也按 session purpose 隔离，桌面刷新令牌不能在原生网页刷新端点换取后台凭据。原生约 30 秒旧令牌容错不足以覆盖桌面丢响应与离线恢复，需实现持久化刷新恢复协议并验证。
- 30 天从这次完整认证完成时计算，刷新不顺延绝对期限；刷新轮换、双窗口单飞与丢响应重试不得意外使正常更新后掉线。
- 服务端每次模型请求检查账号、会话、授权策略及试用是否有效；客户端本地配置不是最终授权依据。
- 停用/撤销后拒绝新请求，并在响应交付前再次检查。客户端在收到授权失效时停止云端 AI 接待、取消在途生成并提示重新登录；授权失败不能走普通模型超时的买家兜底发送。
- 登出清理本机登录凭据、撤销当前会话并广播到主/辅助窗口；网络异常不清空尚未过期的加密凭据，也不谎报已登录或已离线授权。
- 保持现有 appId、userData 路径与会话密钥；发布时不能重新生成服务端 SESSION_SECRET/加密主密钥。升级不重新创建用户或试用。

## 本机数据归属与兼容

新托管账号的本机数据按服务端 origin 和规范 userId 分目录。切换账号前停止旧接待、采集及窗口，不能让另一账号看到前一账号的店铺/会话/模型配置。店铺 UUID 及 session partition 不与新账号共享。

升级机器上的原有本地工作区不删除、不上传。首次明确选择“将已有本机店铺归入当前灵兔账号”时先备份并记录唯一归属，后续其他账号不能再次认领。此迁移只发生在本机。

默认提供托管模型模式；已有用户自带 Key 的直连方式保留在高级设置，并与托管登录凭据隔离。不得把旧 Key 自动上传到服务端，或在托管权限失效时静默切到其他账户/模型。AI 接待仍需显式开启，沿用现有启动默认关闭规则。

## 试用与计数

- `trial_grants`：规范用户唯一的 signup grant，默认 limit=20、expires_at=grant_created_at+7天。身份验证成功、规范用户创建后在同一事务或可重试幂等流程中发放。
- `trial_requests`：以 `(user_id, client_request_id)` 唯一的请求记录，保存请求摘要、预占/成功/失败/不确定状态及用量元数据。
- 新调用在事务中验证 `成功次数 + 在途预占 < 次数上限` 和未到期，先预占再调用上游。最后一次额度的并发请求不能同时通过。
- 相同请求 ID、相同请求摘要不重复转发和扣次；不同摘要使用同一 ID 返回冲突。短期缓存的结果若落盘必须加密并到期清理，不作为永久聊天日志。
- 成功且可用的模型结果扣 1 次。明确失败释放预占；断网或崩溃导致结果不确定时保留记录并进入对账，不能立即放开导致重复消耗。客户端提示待确认并保留输入，不自动重复发送同一次请求。
- 全局默认变更只影响新发放试用；老账号的剩余次数/期限由明确的后台调整操作修改并记录原因。重新注册、恢复账号或更新不会重置账本。
- 初始运行参数（实现建议，后台可调）：每账号 1 个在途调用、每分钟 5 次；全站最多 4 个在途模型调用；每日全站试用调用上限 200；单次默认输出上限 512 tokens。该上限只是保护初期公共注册消耗，不包含付费方案。

## 模型调用与配置

客户端只获取模型显示名、允许的模型 ID、默认模型、试用余量和账号状态；不获取渠道 Key、SMTP 密码或 OAuth Secret。服务器只接受带模式约束的配置，不能下发脚本、插件或本机浏览器执行命令。

`POST /api/client/chat/completions` 验证会话和试用，按账号/分组策略选择 DeepSeek 或千问，再复用 New API 的模型调用链。请求中的用户 ID、分组、渠道、费用和 token 标识不可作为权限依据。托管客户端账号禁止绕过此端点直调 `/v1/*` 或自行创建 New API Token。

托管账号的浏览器会话同样受到限制，包含原生 `/pg/chat/completions` 与 Token 管理入口；不能仅隔离桌面令牌而留下网页调用绕过试用账本。

管理员可以设置全局默认模型和单账号覆盖；启用的模型必须有测试通过的渠道。服务端策略每次调用生效，不依赖客户端升级；客户端在登录、重新聚焦与定时同步时刷新展示配置。

上游 Key、OAuth Secret 和邮件密码以版本化 AES-GCM 密文存储，加密主密钥只放服务器私有配置，不入仓库/构建包。涉及 Key 读取/测试/模型适配的实际路径均要验证解密覆盖；不得只把管理页显示为星号当成加密。后台密钥字段默认不回显，留空保持；替换和清除是明确的不同操作。

默认不保存买家聊天正文、验证码、令牌或 Key 的日志。使用记录仅包含账号、时间、模型、成功/失败、调用次数、token 用量与诊断码；管理员操作独立审计。

## 管理页面与客户端界面

管理页面复用 New API 管理台，增加灵兔账号/托管服务入口与试用字段，首批包括：

1. 概览：账号、试用消耗、近期错误、默认模型与服务可用状态。
2. 模型与密钥：DeepSeek/千问渠道、Key 替换/清除、连接测试、启用状态。
3. 账号：搜索、查看绑定方式、余量/期限、授权模型、启停用和撤销会话。
4. 试用规则：默认次数、期限、全站保护上限及单账号调整。
5. 使用记录与审计：筛选、分页、元数据查看。
6. 登录与邮件配置：微信/钉钉应用配置、回调地址显示、邮件配置与验证。

管理员入口必须由服务端角色检查保护，敏感操作沿用上游重新验证和 Security Proof；客户端普通用户不能通过修改前端进入管理 API。

客户端沿用灵兔蓝白样式与现有可编辑 UX25 账号页，新增登录状态、登录入口/登录面板、当前试用余量、退出和重新登录；未配置的入口不伪装成功。新的布局先按用户选择进行可点击预览或直接实现，不擅自重绘已有店铺画板。

## 部署与地区访问

- 候选域名为 `account-kefu.lttlt.top`（公共登录/注册前端）、`api-kefu.lttlt.top`（统一真实后端）。未修改 DNS；本机 DNS 返回 198.18.0.0/15 代理假地址，不能用这个结果判断域名是否被占用。上线前查权威 DNS 与现有 Nginx 配置，避免覆盖已有站点。
- 面向公众的页面采用同一自定义域名双端：大陆阿里云 A 记录、境外 GPT Sites CNAME，保留 API/鉴权/数据库统一后端。海外前端必须连接真实 API，不能用静态快照冒充登录或后台。仅对实际前端 origin 放行跨域，不能用 `*` 搭配凭据。
- 管理后台可保持受鉴权保护；不复制任何账号、Key 或私有业务数据为公开静态内容。
- 服务器候选目录 `/opt/lingtu-kefu/`，独立 releases/current/shared、容器、SQLite 数据卷与仅回环监听的新端口；端口和路径确认未占用后才使用。首次试运行单容器内存上限 256 MiB，Go 内存软目标低于上限，模型并发 4；达不到基线验收时不在现有业务机器上强行上线。
- 使用 GitHub 构建镜像/产物，本机和服务器验证同次构建；保留前一 release、数据库升级前备份及回滚步骤。数据库变更不能靠降级旧二进制假装可回滚。
- TLS 复用现有 `lingtu-acme-renewal` 受限实例角色及 `/run/lingtu-acme-renew.lock`；新增验证 CNAME 和证书域名清单须核对实际配置。必须实际执行续期测试，不以 timer 存在代替验收；不保存长期 AccessKey。
- 初始管理员在回环/private 初始化完成前不公开 setup/管理服务。注册在至少一种已验证登录方式与默认模型准备好前不宣传为完整可用。
- 安装器、镜像和大文件继续使用 GitHub，不占用户 3 Mbps 服务器带宽作为下载镜像。

## 安全与验收

按上游 AGENTS 要求落实适用的 OWASP Authentication、Session Management、OAuth/设备授权和 CSRF 指南；不宣称通过未执行的认证或合规认证。

必须覆盖：
- 未配置、拒绝授权、错误 state、过期/重放回调、重复身份、绑定冲突和邮箱未验证不发试用。
- 试用 20→0、7 天边界、并发最后一次、同请求重复/不同摘要、明确失败与不确定结果、管理员调整和重启不重发。
- 普通用户伪造管理员/分组/额度、绕过客户端端点、令牌跨 audience、会话撤销/账号停用、跨用户读取及 Key 泄漏回归。
- 30 天绝对期限、自动刷新、刷新并发、丢响应重试、服务器重启/客户端升级、主辅助窗口同步和系统加密不可用。
- 本机账号隔离、旧工作区认领确认与备份、账号失效不向真实买家发送兜底。
- 大陆/境外登录页与同一 API、CORS、实际 HTTPS 与续期、容器重启、数据恢复和回滚。
- OAuth 与 SMTP 先使用本地 fixture 做协议失败测试；生产验收必须由用户完成微信和钉钉实际扫码，并确认邮件真实收到。fixture 成功不能代替真实平台验收。
