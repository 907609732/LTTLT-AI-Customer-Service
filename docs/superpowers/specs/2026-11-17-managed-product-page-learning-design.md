# 托管模型商品详情页学习设计（待确认）

## 意图与已确认范围

面向**使用灵兔托管模型的用户**，在现有知识库中把已登录平台的商品详情页作为可追溯来源：直接读取页面文字、商品字段、图片及可取得的视频，由托管模型整理商品知识草稿，经人工审核后才可用于接待。用户已确认**上下文规则应可在服务端后台配置**，而非写死在客户端或只下发一个能力开关；以下接口、顺序和限额是基于现有工程提出的实现方案。

本功能不改变本机自带 Key 用户已有的学习路径；不把网页文字或模型输出当成指令，不自动发布草稿，也不自动开启或发送客服回复。当前先接拼多多已登录商家详情页，其他平台须各自验证页面身份、字段和媒体读取后接入。

## 当前基线与约束

- 与截图对应的知识库实现已在 `electron/knowledge/collector.ts`、`collector-materials.ts`、`source-pipeline.ts`、`learning.ts` 和 `KnowledgeManagerView.vue` 中接通：平台详情字段及图片采集、原料分版本保存、本机 OCR 辅助、视觉模型校对、分块学习、待审草稿和来源审核。旧 `client` 检出不含这套实现，实施前以最新集成基线重新核对。
- `platform-product-dom.ts` 已从拼多多详情编辑页读取标题、描述、属性、轮播与详情图片及 SKU；`platform-product.ts` 没有视频字段。图片经受限 HTTPS/CDN、店铺 Session 与字节校验进入知识库。
- 服务端 `/api/client/config` 目前只返回模型目录与统一 `max_tokens`，**桌面尚未读取此接口**；`/api/client/chat/completions` 仅接受文字与受限 PNG 图片，并按当前统一策略计费。现有托管默认输出上限为 512 token，会覆盖客户端学习请求中的 4096；不能仅把 `video: true` 下发客户端就声称视频学习可用。
- 账号/店铺知识仍在本机 SQLite，托管服务只处理受限模型请求。服务端可以强制模型、用量、并发和提示词策略；若未来要求服务端独立核验每条知识是否已审核，需要另行设计已审核知识同步与撤回协议。

## 方案比较与选择

| 方案                                               | 取舍                                                                                                   |
| -------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| 托管服务直接抓商品 URL                             | 服务端拿不到桌面已登录页面的状态，平台限制和店铺身份难核对；不采用。                                   |
| 把整页截图与整段视频直接交模型                     | 初版接线少，但难对齐 SKU、来源位置、价格时效和审核证据；大文件还会穿过低带宽服务端；不采用。           |
| **沿用客户端只读平台采集，托管服务决定模型与策略** | 复用现有已登录页面、来源版本、学习任务和审核门；需补视频媒体、安全上传及服务端按用途的约束；**采用**。 |

成熟工具调研：项目已有 Electron WebContents 与平台专用解析器，当前无需再引入 [Crawlee](https://github.com/apify/crawlee)（Apache-2.0；适合通用爬虫，但会重建浏览器/登录链路）或 [Mozilla Readability](https://github.com/mozilla/readability)（Apache-2.0；面向文章正文，不能替代商品 SKU/属性定位）。[yt-dlp](https://github.com/yt-dlp/yt-dlp) 的源码以 Unlicense 发布、打包产物有其他许可，且不应以通用下载器绕过平台登录或媒体限制。视频转码若确有必要，再按 [FFmpeg 许可](https://github.com/FFmpeg/FFmpeg/blob/master/LICENSE.md)与发行方式单独评估。阿里云[视觉理解文档](https://help.aliyun.com/zh/model-studio/vision)和[兼容接口文档](https://help.aliyun.com/en/model-studio/qwen-api-via-openai-chat-completions)说明部分 Qwen 视觉模型支持视频文件 `video_url` 或图像序列输入；具体已配置连接须做隔离能力验证。

## 用户流程

1. 用户在本店商品卡选择“从详情页学习”。客户端复用现有**在售商品**目录和详情采集器，核对平台账号、店铺、商品 ID、SKU 集合、页面来源及采集范围；先保存版本化原料，不调用模型。商家编辑页里仅商家可见、未发布或已下架的内容不自动形成对买家的承诺；无法证明买家可见的字段在审核页标为“商家资料待核对”。
2. 页面可读文字、结构化 SKU/属性直接成为文本来源，**不经过 OCR**。商品图直接交支持视觉的托管模型；此路径不要求先做本机 OCR，现有“识别图片文字”仍可供其他资料使用。
3. 有视频时，客户端确认媒体确实属于该详情页及当前商品，读取 MIME、大小、时长和可访问性。托管服务声明支持直接视频时，使用短期受限对象存储上传凭证让客户端直传媒体，服务端持有临时读取地址并以 `video_url` 调用已配置的视频模型。原视频不得经 3 Mbps 业务服务器代理；不得把供应商 Key 或长期对象存储凭据下发客户端。视频含语音讲解时，另由已配置的云端语音识别处理，并把转写文字与时间段绑定；未转写成功就明确标记“只分析画面，语音未学习”。页面只给出无法读取、DRM、分段协议不受支持等明确状态，不尝试绕过限制。
4. 预估弹窗显示本次文字、图片、视频覆盖与缺项、策略版本、调用上限及费用估算范围。视频不可用时，用户可明确选择只用可用来源继续，草稿标记覆盖不完整；不得自动宣称“已学完视频”。
5. 托管模型输出受限结构化候选：问题、答案、字段类型、店铺/商品/SKU 范围、精确 sourceId+revision 和文本位置/图片资产/视频时间段。服务端的模型提示词、路由和额度规则不下发原文；客户端只接收能力、限额、版本与可展示的说明。
6. 候选沿用现有草稿与人工审核，审核页可打开原文、图片或对应视频片段。没有可复核依据、范围不符或来源变化的候选拒绝入库。审核发布后继续由现有本店检索、有效期与发送前知识复核约束接待。

## 服务端可配置上下文策略

管理后台增加“上下文策略”配置页，复用现有管理员会话、敏感配置安全证明、审计及 `lingtu_settings` 存储。第一版是一份全局托管策略，适用于全部托管账号；套餐或账号覆盖需要独立的优先级与授权规则，后续再加。管理员可编辑并预览生效版本：

| 配置                                                             | 服务端保存与执行                                             | 客户端所见                           |
| ---------------------------------------------------------------- | ------------------------------------------------------------ | ------------------------------------ |
| 接待系统规则模板、禁答/转人工边界                                | 保存原文，服务端组装托管模型请求                             | 仅显示策略版本与简短说明，不下发原文 |
| 已审商品、店铺和模板知识的检索顺序及知识预算                     | 保存配置；客户端按顺序从本地已审库检索，服务端再验总输入上限 | 下发可执行的顺序与 token 上限        |
| 学习允许来源、视觉/视频/语音模式、单商品调用和输出预算、必须审核 | 保存配置；服务端校验学习用途和模型能力                       | 下发可用功能、额度估算和禁用原因     |

检索顺序只决定**已通过现有范围、冲突和有效期校验**的知识如何填入预算；后台不能改变 SKU/商品覆盖关系、冲突胜出规则或把模板排在商品事实之上。通用表达始终是低优先级的语言参考，不允许通过后台配置提升为商品事实或放入更高信任的知识来源。现有正式回复的 16K 触发、8K 压缩目标和受保护近期原文规则保持约束；后台可设的知识预算不得突破它们。

保存要求整数 `revision` 乐观锁、字段白名单、范围校验和操作审计；保存成功后新任务取得新版本，进行中的学习任务因策略版本变化暂停并重新估算。服务端不可用或策略读取失败时，新托管学习功能不可启动；旧客户端的既有聊天兼容行为不因新增配置而改变。客户端不能通过修改下发 JSON 放宽服务端上限。

**作用边界**：本店知识仍在本机，服务端不知道本地 SQLite 的实时审核状态，因此检索顺序由客户端按下发配置执行，已审核校验继续由本机知识库及发送前复核负责。单商品调用上限由本机学习任务执行，服务端额外强制账号级额度；在没有可信商品身份同步前，不能声称服务端已独立证明商品级上限。服务端独立执行隐藏提示词、模型选择、输入/输出上限、账户额度和媒体访问控制。若以后要让服务端独立证明“某条知识已审核”，需要同步审核版本、撤回和店铺绑定，属于单独项目。

## 策略接口边界

- 在已鉴权的 `/api/client/config` 增加向后兼容的 `learning`/`runtime_context` 能力摘要：`policy_version`、`enabled`、允许来源、视频模式、单次来源/字节/时长/调用上限、输入/输出预算、`requires_review`、知识检索顺序与预算。桌面主进程需要新增**受限、定型的配置读取通道**，不能把字段只写入 `/me`（现有 vendor 会话校验会丢弃未知能力字段），也不能把管理或任意 URL 请求开放给渲染端。旧客户端忽略新字段；旧服务端无字段时新客户端显示未开通。配置随账号和服务来源刷新，过期或来源切换时不得沿用。
- 服务器保存**真正隐藏**的系统提示词、模型路由、价格、套餐门槛和上限；客户端可见的 JSON 不是秘密，也不能作为唯一保护。学习请求要带用途、策略版本和稳定请求 ID，服务端重新校验账号、策略、模型能力、额度、媒体约束和费用，再复用现有预留/结算/未知结果机制。学习用途的服务端输出上限须单独允许经核验的结构化草稿，不能继续沿用当前默认 512 token 造成 JSON 截断；上限仍由服务端决定。学习调用与普通聊天/摘要的账本用途分开，不能因客户端字段改写绕过限制。
- 现有 `KnowledgeModelPort` 负责模型调用，学习任务继续用已持久化的 submitted/received 检查点。新增视频来源时须同步采集器的静态/图片/动态来源分类、学习来源白名单、证据校验和备份闭包；视频节点不混入现有“已上传 N 张图片”的计数，也不挤占图片 50 MB 配额。策略、来源版本或账号租约变化时暂停并重新估算；不确定请求由用户明确重试或跳过，不自动重发计费调用。
- 商品知识仍在本地。客户端按服务端下发的检索预算与优先级组装**已审核**知识；服务端额外强制总请求预算和隐藏安全提示词。第一版不声称服务端已独立证明每条本地知识的审核状态。

## 视频证据与数据边界

- 增加受限视频来源和定位信息：媒体哈希、所属店铺/商品、实际页面 URL、采集时间、开始/结束毫秒、必要的可回看片段或关键帧。模型只能引用当前调用携带的媒体和时间范围；时间点无法核对时不产生可发布事实。只由声音表达的卖点需要独立云端语音转写及人工核对，不能由不含音频能力的视觉模型猜测。
- 临时上传必须绑定账号、工作区、商品和请求 ID，限时、限大小、限 MIME/哈希；服务端只接受自身签发的媒体对象，不抓任意客户端 URL，防止 SSRF 与跨租户引用。默认仅使用当前托管模型所在境内区域的受控对象存储与供应商；没有同区域可用上传与模型路径时视频能力保持关闭，避免临时转到其他地区。临时云对象到期删除；审核证据及必要的本地片段进入知识库备份/恢复范围。平台原始登录凭据、Cookie、请求头不入库、不上传。
- 页面文字、图片和视频都视为不可信资料。模型输出仅为候选，不允许资料里的指令改写系统策略，也不能从视频推断未展示的规格、兼容性或售后承诺。

## 分阶段交付与验收

1. **服务端配置与直接详情页文本/图片学习**：先做管理员“上下文策略”页、持久化与审计、客户端生效投影、隐藏提示词和服务端额度约束，再接无 OCR 的详情页来源路径；沿用现有审核队列。用合成平台页和模拟模型验证来源绑定、OCR 未触发、旧客户端/旧服务端兼容、策略变化暂停、服务端越权拒绝与管理员保存冲突。
2. **直接视频学习**：在视频模型、同区域临时对象存储及语音转写路径真实可用后，接详情媒体、直传、`video_url`、语音时间段、回放审核与备份。用短合成视频验证完整链路、超限/失效/取消、跨店隔离、费用不确定状态；真实店铺和真实托管模型另做授权后的验收，不能用夹具宣称已支持所有平台视频。
3. **接待上下文策略**：在现有本机审核检索器上按服务端预算和优先级组合知识，并在托管端限制最终请求。验证撤回、过期、换店与待发候选失效，不绕过既有发送确认门。

本设计只涉及本机代码与隔离测试；生产部署、真实商家平台和收费模型调用需要按项目现有交付边界另行安排。
