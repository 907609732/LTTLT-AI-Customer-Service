# 店铺向导复用配置实施计划

用户已批准本方案并要求实施。Codex负责范围、复核、集成和本机验收；本机DeepSeek负责独立工作树内实现。

## 目标及约束

引导首页增加“复用其他店铺配置”，只在有其他店铺时显示。允许跨平台选择当前工作区的另一个店铺，四类默认全选：客服风格、物流与发货政策、接待设置、售后政策。确认“填入并继续设置”只修改当前店草稿，进入步骤1；最终保存统一写入。一次性复制，不建立关联。已有草稿需明确替换确认；取消不改草稿。来源未配置的项保留目标值并提示。

接待只包含文字欢迎及启用状态、本店转人工关键词/继承状态。不复制平台人工账号、媒体、平台规则、全局配置、商品、凭据、登录、历史及AI开关；不执行平台动作。复用模式下接待表单延后最终保存，普通原有设置维持独立保存。最终按钮前显示来源与类别摘要。必须能修改导入内容。

## 复用决策

采用已有Vue 3 / Element Plus 2.8.8表单、setup-rules的规则读取/克隆绑定、接待草稿缓存及save-welcome/save-store-handoff命令。不引入新依赖、持久格式或任意JSON写入。旧同步页已被用户移除，不恢复其入口，也不扩展商品同步。已检索Element Plus官方GitHub表单实现，其通用表单不能代替本工程店铺租约和业务并发校验。

## 顺序任务

1. 服务及状态：先添加失败测试，再扩展setup-rules只读来源信息/是否已配置的表达，新增明确的四类字段选择映射和导入草稿协调。绑定当前workspace/目标store/引导租约；取消、切店、移除来源、乱序响应不落入其他店。源数据只读。来源规则读取不可覆盖目标保存服务的baseline。
2. 接待草稿与最终保存：先测不落盘、可编辑、重开保留、目标冲突和部分失败再实现。跨模块公开入口传递typed draft/events，不从shops访问reception内部。欢迎语使用目标版本，转人工比较目标基线；复制值不得带来源版本。保存前预检目标对应配置；按项目既有命令保存和回读；政策、欢迎、转人工各记成功/失败，部分失败保留草稿并仅重试未完成项。完全成功才显示完成；后续编辑需取消相关成功标记。非复用路径行为不变。
3. 界面：独立来源选择弹窗，默认四类全选；来源名称/平台、跨平台核对提醒、范围和缺项提示、明确替换确认、加载/失败/重试。使用现有助手样式和Element Plus组件，不恢复旧同步界面。统一保存模式隐藏导入的本店接待独立写入按钮并显示待保存提示，不影响全局配置原流程。
4. 验证及交付：运行相关向导、规则、接待和新增测试；修改文件ESLint/Prettier、相关类型检查及build；新增一个隔离桌面场景验证来源选择→导入→检查→保存→回读、源店不变、AI不开启。更新向导/模块/HANDOFF文档。Codex独立审查并补充风险测试后整合主目录，版本只增加一次，重启主项目并核对实际版本。不要运行全量Release验证，不公开发布、不部署、不发买家消息。

## 验收矩阵

同/跨平台、部分选项、未配置来源、空值/显式false、取消/覆盖确认、重复导入、来源/目标移除、过期异步响应、工作区切换、目标冲突、部分失败重试、接待编辑及草稿恢复、持久化重启回读、源店及全局不变。
