# 拼多多添加后登录与自动识别实现计划

目标：确认添加拼多多网页店铺后直接打开平台，登录后自动保存并展示店铺与客服身份。

用户已批准本文所对应的流程并要求直接修改和测试。复用现有 Electron WebContentsView、独立持久会话和适配器，不添加依赖。现有工作区有未提交功能，按文件最小修改并保留这些内容。

- [x] 先添加失败回归：无名称建店并自动打开、打开失败保留可恢复记录、空名与身份持久化。
- [x] Registry 允许拼多多未命名，保存 mallId/customerServiceName/customerServiceId；其他平台保持名称要求。
- [x] PDD 适配器提供只读登录身份探测；只在平台来源运行，以页面账号数据和同会话 GET 资料识别，排除登录页与失败响应。
- [x] ShopWindowManager 在加载、导航和定时探测中更新登录/身份状态，串行探测，关闭与导航令旧结果失效。
- [x] 前端确认即添加打开，移除拼多多命名步骤；统一空名占位与登录/识别状态，提供打开重试。
- [x] 执行 typecheck、单元测试、后端测试、build、E2E 和受控真实 Electron 集成测试；实际平台只读验证登录页，不向买家发消息。

验收边界：受控平台响应验证登录前后、识别失败重试、注销、重载、关闭竞态和磁盘恢复。真实扫码登录需账号持有人完成后才能核对真实店铺名，不能用模拟结果冒充实际平台验收。

方案来源：Electron 官方 WebContentsView/session 文档（MIT，沿用已安装 45.2.3）；GitHub Geek-master-100/ai-customer-reception 与 renchengxiaoqiang/pdkbot 的公开账号读取片段仅作接口字段交叉参考，许可证未明，不复制代码或引入依赖。

验证记录与实际平台验收边界见 docs/PDD_LOGIN_FLOW.md。全量 E2E 的旧看板快捷入口失败已明确记录，未标为通过。
