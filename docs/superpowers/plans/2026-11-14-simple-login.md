# 简化登录实施计划

> **For agentic workers:** Use superpowers:subagent-driven-development to implement and review each task.

**Goal:** 顶栏只保留登录入口，左右并列提供自己的 Key 和服务端登录，普通用户不需要理解服务地址、模型标识或手动重启。

**Architecture:** 复用现有 Vue 3、Element Plus 2.8.8、厂商预设、加密存储和设备授权协议。来源/身份改变时由主进程安全重建运行时与账号工作区，保持每次装配 AI 关闭、旧请求失效以及跨账号隔离。组件只使用现有平台/业务契约。

**Tech Stack:** Vue 3 / TypeScript / Pinia / Electron / Element Plus / Vitest。

## 用户指定设计

- 顶栏“本机密钥模式”和重复模型状态合并为一个登录入口；已登录显示账号名，已配置 Key 显示“自己的 Key”。
- 登录弹窗左栏“使用自己的 Key”：DeepSeek、千问、千问识图预设，API Key，保存并使用。默认接口及模型自动填充，调用已有连接验证。
- 右栏“服务端登录”作为推荐方式：登录、授权中、取消、失败重试、账号/剩余次数。普通入口不显示服务器、API 地址、管理员后台和技术解释。
- 登录成功自动切入对应工作区，不暴露手动保存来源/重启步骤。关闭弹窗清理 Key 草稿，不取消已经开始的网页登录；取消授权需显式操作。
- 回复间隔只在设置页。高级自定义模型配置折叠；仅保留必要错误和操作提示。

## 复用与取舍

采用现有 Element Plus 弹窗、输入框和按钮（MIT，仍维护），不引入新的认证框架或表单依赖。沿用账号网页设备授权，避免建立另一套密码登录。普通控件使用当前锁定版本已有 API，不升级依赖。整应用重启会中断体验，因此选择在主进程重建已有运行时，依然遵守原账号隔离规则；不得绕过 restartRequired 直接开放旧工作区。

## 验收边界

自动验收仅使用隔离数据、模拟授权/模型，不产生真实模型费用，不向买家发消息。页面 HTTP 200 不证明正式授权成功。保存/登录失败不得显示可用；更换身份与来源不得访问旧账号资料；密钥不进入 URL、日志、明文存储或业务快照。
