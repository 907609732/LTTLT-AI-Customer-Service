# 知识库实施取舍与代价

以下仅记录统筹在用户已确认需求内作出的工程裁决，不是新的需求或发布授权。按决策先后排列，作为本分支正式交付记录。对应验证见 [KNOWLEDGE_ACCEPTANCE.md](KNOWLEDGE_ACCEPTANCE.md)。

1. 使用原生工具创建的独立工作区，保留原目录及其他工作区的未提交修改。代价：原目录未提交的品牌/样式不会自动出现在本知识库分支，需要后续明确集成。
2. 按用户规则只跑修改及直接影响的验证，不默认跑全量check/上游/Release。代价：未受影响的其他模块不由这次结果作完整保证。
3. 复用Electron43/Node24内置SQLite，单写入器、短事务，解析/模型等待不占事务，不新增数据库服务。代价：运行环境需支持该Node/Electron能力，安装包仍须在正式Release时验收。
4. 同款关联按根商品及全部SKU一次确认、一次事务更新；SKU是店内规格/覆盖，不独立指向另一共享商品家族。代价：未来如需跨家族独立共享SKU，要显式新增变体模型。
5. 发现原目录分支落后后，隔离分支改以实际main=f2193fc为基线，复用已验证平台读取器。代价：最终代码包含该main已有功能；知识库改动需按此基线比较，而不是旧02c9286。
6. 保留main已存在的发送授权模式和AI开关，知识引用校验接入原统一发送门，不额外授权自动发送。代价：知识库不替代原发送模式的独立治理和实店送达验收；旧规划的逐条确认措辞按实际已授权基线处理。
7. 迁移平台商品归档只作为原始资料；旧已启用商品/意图保留状态，之后新保存/导入/模型结果必须审核。代价：原始详情迁移后不会立刻变成AI可承诺的知识，需要学习及人工审核。
8. 商品备份按共享商品全家族，包含所有店铺/SKU以及原件、来源、历史、审核和证据依赖；恢复保留无关家族。代价：备份可大于一个店铺的单商品导出，原文件可能包含其他商品行，预览必须披露。
9. 恢复由工作区所有者停止真正的写入器，保留恢复点，再重建同账号运行时和租约；不用切模型来源或改AI开关强制刷新。代价：恢复会暂时停止本账号服务/任务，按现有启动默认保持AI关闭，不能只热替换数据库文件。
10. 数据库替换中途若进程退出，下一次启动检查持久恢复意图，停止新库创建、保留所有副本并给出恢复提示。代价：需明确维护恢复操作，不能猜测应自动启用哪个半完成副本；已生成且内部自动冲突键超长的旧坏备份仍严格拒绝，应先修复本机历史再重新备份。

额外边界：独立知识库窗口关闭仅隐藏，学习付费不确定调用不自动重试；日检只读不学习。实店PDD/CDN、真实模型语义/OCR、托管计费和正式安装包未由本轮隔离夹具验收。该边界由最终报告继续明确。
