## 必须遵守的边界

1. `src/app` 负责启动、路由、布局和服务装配；`src/modules/<name>` 负责业务；`src/shared` 只放跨业务复用的能力与契约。
2. 依赖只从 app 指向 modules/shared，从 modules 指向 shared。跨模块只经 `index.ts`；shared 不得反向依赖 modules/app。
3. 组件内不得直接使用 fetch、Axios、localStorage、sessionStorage、Electron、Node.js 或 `window.yunduoDesktop`。业务数据经过服务接口；桌面操作经过 `shared/platform`。
4. 渲染层和桌面源码使用 TypeScript；公共输入、输出、组件 props 与事件必须有类型。不允许新增 any、ts-ignore、ts-nocheck，或通过关闭严格检查消除问题。
5. 局部表单与弹窗用组件状态；跨页面共享状态再使用 Pinia。避免把所有业务塞进一个 store 或 feedback 工具。
6. 演示数据由模块 `demo` 工厂生成，每次调用返回独立数据。不得伪造函数、数组方法、授权状态或业务执行成功。
7. `notifyUnavailable` 只供显式业务动作调用。不得恢复全局点击兜底，不得把导航、输入、关闭弹窗当成未接入业务。
8. 弹窗通过 v-model/props 和事件控制。提交按钮在服务未接入时明确提示；关闭、取消等本地操作必须可用。
9. 不修改生产软件、安装目录和项目外的还原工具。历史生成器不得覆盖当前源码。

10. `vendor/lingtu-runtime` 是固定提交的第三方 JS/CJS 兼容例外，来源与许可证见其 PROVENANCE.md。默认原样复用，最小兼容补丁须记录来源及双哈希并运行上游测试；本工程新增业务和适配仍使用 TypeScript。禁止将自有新代码放入 vendor 规避检查。

11. 默认保留本机自带 Key；按用户最新要求新增显式托管模式与独立 server 目录。切换来源或账号必须停 AI 并重启，托管业务目录与平台分区按来源和已验证账号隔离；不混用原本机资料，不回退本机 Key。刷新令牌仅主进程系统加密保存，不回传快照/日志。详情见 MANAGED_SERVICE.md。

12. server 是固定提交的上游 Go/原生 React/已有 JS 源码导入例外，保持许可与哈希，不导入上游桌面界面。该目录独立做原生类型/测试/构建，根格式检查排除导入文件；新增 verify.ts 单独纳入 TypeScript/ESLint 检查，不能把桌面自有代码放入例外。禁止自动执行生产部署脚本。

13. 本机图片识别复用当前模型配置，不按模型名称设置白名单或强制特定服务商。用户负责选择支持图片输入的模型，先在训练场验证；不支持时如实报错。vendor 仅保留有来源记录、原始哈希与实际哈希的最小兼容注入点，策略写在 electron/model-capabilities.ts。

## 编码与注释

通用话术只能使用审核过的内置改写，每轮最多 3 条，仅作为表达参考，不作为本店知识或操作证据。不得把原始 FAQ/规则、未审核候选或用户文字放进受保护的系统参考块。插入必须在 token 计量之前，保留本店规则、压缩预算与逐条确认。复制 IPC 只接受已知话术 ID，不开放剪贴板读取、任意内容写入或发送能力。详见 GENERIC_PHRASES.md。

正式回复的上下文必须按 storeId + uid 合并本机归档、平台历史和当前批次，包含买家与实际客服回复；禁止只用本轮队列或提前截成 20 条。平台历史失败不得丢弃归档，未确认候选不能冒充已发送回复。原文超过预算由统一压缩器处理；未知的历史范围不能声称完整，当前归档上限仍为每会话 100 条。

逐条买家消息的 AI 状态必须依据引擎/请求证据，不把采集、准备 messages 或摘要请求冒充正式回复请求；历史无证据显示未知。正常节流仅原地更新原因，不恢复刷屏日志。新消息替代旧候选不能永久暂停新消息，用户主动取消及人工接管仍需显式恢复。回复间隔在设置可改，0～3600 秒，保存不得自动启用 AI 或改动凭据。见 MESSAGE_AI_STATUS.md。

用户日志缓冲不记录 reply:throttled（包括 uid_interval、store_rate 等正常轮询节流）；不得为减少日志而删除限流保护。AI 回复耗时从 AiClient 收到生成请求计至清洗正文完成，使用单调时钟，包含上下文准备/压缩，排除人工审批、逐字输入和发送。失败、生成中或旧记录不能伪装成功的 0ms 耗时。

拼多多通过用户确认后采用逐个可见字符输入，生产默认 50ms/字符；禁止恢复成一次性填满整段。emoji 按字素处理，不拆散组合字符。逐步核对目标买家、原有前缀、焦点及网页消息；AI 停止时取消输入，完成后再单次点击发送。中断保留部分草稿，不覆盖人工改动，不自动清空或重发。测试可显式加速，但生产速度常量由 TypeScript 维护。

发送确认不得把私有历史接口读取失败冒充新消息，也不得用跨来源的消息 ID/时间戳精确相等判断同一消息。拼多多使用生成前和确认时的网页消息基线，绑定店铺、买家和页面实例；临时不可读保留待确认状态，真正变化或停止 AI 才作废。不能通过跳过复核修复误拦截。

上下文达到估算 16,384 token 时触发摘要，正式请求目标不超过估算 8,192 token；统一口径和图片预留见 CONTEXT_COMPRESSION.md。系统规则、受保护近期原文和图片不裁剪，摘要作为不可信资料。失败不回退发送超限请求，不跨店铺/买家复用摘要，不绕过用户逐条发送确认。新增 tokenizer 依赖及上游注入点须同步维护来源和验证。

当前本机模式 AI 回复必须逐条经用户明确确认后才调用发送适配器，不能以打开日志窗、启用 AI、超时或恢复应用代替批准。转人工提示也经确认；自动超时兜底停用。新消息、人工回复、停店或停止 AI 使旧候选失效。调试仅保留有界内存，不记请求头/密钥，不向外上传买家上下文。完整状态及维护规则见 RUNTIME_LOGS.md。

拼多多网页版文字发送固定使用 DOM：填入网页输入框并点击发送按钮，不使用系统鼠标；按钮坐标仅来自网页 DOM，通过该 WebContents 的浏览器内部鼠标事件触发，不自动降级为回车。已有人工草稿、会话不匹配或填入内容被改写时不点击。点击后核对新卖家回显，结果不确定不重试。抖店客户端桥接属于另一适配器，不把拼多多 DOM 验证结论套用到抖店。

- 用业务含义命名状态；禁止新写 state1、mock1、computed1。已有临时视图字段改动时应同步明确其含义，无法确定的业务在交接文档中登记。
- 注释说明“为什么”：业务约束、兼容原因、安全限制、错误处理和复杂状态转换。不要逐行翻译代码。
- props 向下，事件向上；组件不得直接修改传入的表单配置。编辑时创建草稿，保存成功后才更新确认状态。
- 可见列表使用稳定业务 id 作为 key；纯演示的固定空列表允许使用局部序号，接入真实数据时必须替换。
- 维护加载、空数据、失败、重试和取消状态；对异步请求处理拒绝和卸载，避免重复提交。

## 真实功能接入流程

1. 在模块内定义 `contracts.ts`（输入、输出和失败形式）；先确认后端资料，不臆造 URL、鉴权、金额单位或平台授权流程。
2. 在模块 `services` 中实现接口；组件通过模块 composable/store 使用服务。在 app 中选择演示或真实实现，不在组件里判断环境后直接发请求。
3. 服务中的数据必须按账号/店铺隔离；退出账号时清除相关内存状态。敏感凭证不得放入源码、日志、演示数据或渲染层构建产物。
4. 需要新的桌面能力时，同时修改共享契约、preload 和主进程处理器；校验发送来源、参数与允许的资源范围。不得暴露 ipcRenderer、任意通道或任意文件操作。
5. 先完成一个可独立验收的业务流程，再扩展下一个。不得仅替换 `notifyUnavailable` 为网络请求。
