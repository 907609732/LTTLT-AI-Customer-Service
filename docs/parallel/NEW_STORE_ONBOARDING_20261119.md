# 新店八步引导源码交付

## 已完成

按用户确认的方案整合现有流程：登录 → 导入商品与学习 → 客服风格 → 物流与发货 → 接待设置 → 售后政策 → 确认信息 → 完成。所有新增店铺统一入口，已有店铺基础设置仍保持原六页助手。新店登录自动检测不跳步；点击“我已登录”重读当前平台状态，核验后才进入导入。新增流程不要求手填店名。

知识导入复用现有 client/query/pipeline。拼多多预览当前在售目录并提交精确选中范围，单次最多1000件；闲鱼/其他平台沿用文件预览、导入或跳过，本次不新增平台采集。模型学习明确估算并确认，文件学习从实际导入任务 checkpoint.sourceIds 取拆分产物，采集学习仅使用本次任务的绑定及更新来源。不学习原文件，不混入其他历史任务，不自动发布。

进度来自持久任务；未知总数用等待提示，空结果/部分完成/取消/失败均与成功区分。提交结果未知或无有效任务号时闭锁再次提交，不因断线重复消耗额度。任务可取消，或明确继续后台执行后退出/继续设置；跳过显示稍后补充。基础设置复用既有表单及保存流程，确认页明确保存成功后才进入完成；返回首页清原生平台展示，不开启AI。

## 原生布局与兼容

presentStore 在原接口增加可选 default/onboarding-login 枚举，服务主frame继续严格校验；主进程仅选72/216两个固定顶边。vendor platform-host 保留最小布局补丁，维护原始Git来源及实际文件哈希。新preload静态声明 onboardingPresentation 能力；旧运行文件缺少能力时回退原流程，避免前端热更新后原生页面遮住步骤条。

每次打开目标重建异步版本租约；相同工作区的托管账号/来源改变也清除会话，不能只靠workspaceId判定账号。其他店铺数据和当前主目录未提交内容未修改；本分支不调整主线版本。
