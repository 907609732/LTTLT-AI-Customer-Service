## 整合顺序

1. 检查每个交接和实际 diff；保留接手前全部未提交改动，不重置、不全目录格式化。
2. 先接本地工作区领域能力：知识、同步、快捷回复、调度和报表。
3. 统一托管主进程认证适配，再接团队和计费；不把 bearer 或 refresh token 暴露给渲染层。
4. 接路由和导航；针对界面入口、IPC、账号/工作区切换、持久化和失败边界做集成回归。
5. 按受影响范围运行类型、静态检查、增量测试、构建和隔离桌面流程。未修改且不受影响的上游不做全量回归；vendor 若有改动则执行来源完整性和必要上游验证。
6. 汇总实际交付和外部依赖。没有实店样本、商户配置或平台接口的部分明确记录，不能以夹具成功替代实店验收。

## 统一接线与审查修复

- main 统一注册领域IPC；preload仅固定能力；App provider同时接团队和计费，路由/配置中心可访问同步与团队入口。
- 账号隔离目录为主进程 managed.dataDir，随机workspaceId只校验旧窗口，不进入持久文件名。
- 同步内部直接调用上游版本化服务；同步忙时拒绝公开业务修改，实例dispose清理计划。前后检查账号、工作区与服务实例，拒绝晚到结果。
- 修复真实桌面暴露的同账号快照刷新清空同步预览，新增先失败后通过的Vue回归。
- 统一managed.serviceRequest只允许已实现团队/计费的精确路径及GET/POST，不接受认证头、任意URL、查询串或超过128KiB正文。复用已有加密设备会话、超时、epoch和退出保护。
- 账号认证和AI余额校验分开：额度耗尽/试用到期不能阻止查看/充值，但AI生成继续受原配额限制。
- 报表在managed.init完成及认证变化后观察，账号不可用立即遮蔽旧报表及模拟计数，不导出客户正文/标识/凭据。
- 独立只读审查发现1项P2：同账号重新认证后调度未恢复。已加入认证驱动的start/pause、退出取消pending及异常状态，原生回归覆盖已知账号缺凭据启动→同账号重新授权→运行，以及退出暂停→再次授权恢复。修复后审查通过，无新增P1/P2。
