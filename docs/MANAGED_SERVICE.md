# 本机 Key 与独立托管服务

## 使用

设置 → 模型来源与托管账号，可选择本机自带 Key 或托管服务。现有用户默认保持本机，不读取开发者密钥，不自动登录或开启 AI。原始本机数据仍在原目录，不迁移进托管账号工作区。

远程托管 API 和账号网站必须为 HTTPS 来源，不包含路径、查询参数或账号密码。按用户明确要求，本机预览例外允许带端口的 http://127.0.0.1，后台与 API 同源；启动见 server/README.md。只有点击登录才打开所配置网站的设备授权页；用户在浏览器完成登录和授权，客户端显示确认码、实际账号及分配的额度。可以先在当前来源下登录，再保存托管模式并重启。改变地址后必须先重启，不能把旧来源的凭据发到新来源。

保存来源或切换托管账号后，AI 停止并要求重启。重启后恢复加密会话，使用当前服务/账号专属工作区；首次登录、账号改变或恢复身份与当前工作区不符时，同样禁止 AI 并要求重启。不同账号的店铺、知识、会话、工单、模拟数据及平台登录分区不共用。退出会停 AI 并移除本机凭据；服务端撤销不确定时明确提示，不假称已撤销。

托管调用固定使用服务端分配模型与额度，不使用或回退本机服务商 Key。设置显示总次数、已用、占用、剩余、到期和模型能力，数值来自最近一次服务端同步，点击刷新更新；实际请求仍由服务端做最终资格校验。微信/钉钉/SMTP 及 28 类模型连接配置在独立管理网页中，不在桌面保存供应商凭据。

请求结果不确定、额度不足、账号停用等保留原生暂停与对账提示。用户需核对原会话和服务端用量，再明确勾选清除；清除不会重新请求或自动发消息。AI 正文、转人工提示和欢迎语仍逐条确认，旧候选不因切换而自动放行。

## 代码与数据

- server/ 是固定来源的 Go/原生 React 服务端覆盖层，独立构建，许可、来源和约束在该目录保留。
- shared/contracts/managed.ts 只定义无密钥 DTO；已有业务命令白名单增加来源/登录/退出/刷新/后台入口及明确清除提示，不增加任意网络或文件 IPC。
- electron/managed-controller.ts 复用固定 managed-session.cjs：设备授权、短期访问令牌、加密刷新令牌、刷新轮换和终止会话；凭据不返回渲染层。
- model-source.json 保存模式与公开来源；managed-auth/<来源哈希>/session.enc 保存系统加密凭据，last-account.json 仅为工作区定位标识。managed-workspaces/<来源哈希>/<账号哈希>/ 隔离业务数据；身份标识本身不提供授权，必须与实际恢复的服务端账号相符才放行。
- local-runtime 继续在统一工厂注入平台、完整会话、通用话术、压缩、trace 和确认门；托管 complete 走受限客户端 API。traceId 只在本机 options 转发，不发送给服务端；只有实际聊天 fetch 前发出提交证据，刷新令牌不冒充 AI 请求。
- 托管摘要与正文都属于模型调用，可能分别消耗试用次数；使用服务端的输出/消息限制，失败继续拒绝超限请求，不退回本机 Key 或重发。调试区的模型来自实际账号能力，而不是残留的本机模型配置。

## 验证与运维

先 npm run server:verify，再 npm run check、npm run test:desktop。原生检查用隔离 SQLite 和模型夹具；桌面检查用真实 Electron/safeStorage、临时工作区与回环 HTTP 协议夹具，不登录生产账号、不用付费模型、不发真实买家消息。MySQL/PostgreSQL、真实各厂商和线上 OAuth/邮件需单独验收，不能用上游历史 CI 冒充本次执行。

测试入口只通过 createLocalRuntime 的显式依赖参数注入，不提供生产环境变量或渲染层覆写网络目标。server/scripts/verify.ts 是独立构建工具，另有 TypeScript/ESLint 检查；导入代码由来源清单和原生构建/测试检查，桌面自有新代码继续使用 TypeScript。

切回本机模式并重启可继续使用原本机资料和密钥；托管工作区保留供原账号再次授权使用，不复制或覆盖。生产服务部署、DNS、证书及既有线上数据不由合并和本机测试自动修改。维护修改前必须读 server/CONSTRAINTS.md，禁止将生产初始化脚本用作测试。
