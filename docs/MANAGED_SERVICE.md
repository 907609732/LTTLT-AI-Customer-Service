# 本机 Key 与独立托管服务

## 使用

设置 → 模型来源与托管账号，可选择本机自带 Key 或托管服务。现有用户默认保持本机，不读取开发者密钥，不自动登录或开启 AI。按用户 2026-11-16 明确要求，本机模式与所有托管账号共用同一个本机业务目录和平台登录分区：登录不再切换到空工作区，原有店铺、知识、会话和平台登录态继续可见。旧版 `managed-workspaces/<来源>/<账号>/` 目录保留在磁盘上，但不再读取或自动合并。

远程托管 API 和账号网站必须为 HTTPS 来源，不包含路径、查询参数或账号密码。按用户明确要求，本机预览例外允许带端口的 http://127.0.0.1，后台与 API 同源；启动见 server/README.md。只有点击登录才打开所配置网站的设备授权页；用户在浏览器完成登录和授权，客户端显示确认码、实际账号及分配的额度。可以先在当前来源下登录，再保存托管模式并重启。改变地址后必须先重启，不能把旧来源的凭据发到新来源。

保存来源或切换托管账号后，AI 停止；账号改变后需重启恢复 AI。共用工作区不随登录状态隐藏，登录只决定托管 AI、团队和计费资格；未登录时仍可查看和编辑本机店铺数据。退出会停 AI 并移除本机凭据；服务端撤销不确定时明确提示，不假称已撤销。同一台机器上的不同托管账号会看到同一份本机业务数据，这是取消隔离后的已知取舍。

托管调用固定使用服务端分配模型与额度，不使用或回退本机服务商 Key。设置显示总次数、已用、占用、剩余、到期和模型能力，数值来自最近一次服务端同步，点击刷新更新；实际请求仍由服务端做最终资格校验。微信/钉钉/SMTP 及 28 类模型连接配置在独立管理网页中，不在桌面保存供应商凭据。

请求结果不确定、额度不足、账号停用等保留原生暂停与对账提示。用户需核对原会话和服务端用量，再明确勾选清除；清除不会重新请求或自动发消息。AI 正文、转人工提示和欢迎语仍逐条确认，旧候选不因切换而自动放行。

## 代码与数据

- server/ 是固定来源的 Go/原生 React 服务端覆盖层，独立构建，许可、来源和约束在该目录保留。
- shared/contracts/managed.ts 只定义无密钥 DTO；已有业务命令白名单增加来源/登录/退出/刷新/后台入口及明确清除提示，不增加任意网络或文件 IPC。
- electron/managed-controller.ts 复用固定 managed-session.cjs：设备授权、短期访问令牌、加密刷新令牌、刷新轮换和终止会话；凭据不返回渲染层。
- model-source.json 保存模式与公开来源；managed-auth/<来源哈希>/session.enc 保存系统加密凭据，last-account.json 仅为工作区定位标识。managed-workspaces/<来源哈希>/<账号哈希>/ 隔离业务数据；身份标识本身不提供授权，必须与实际恢复的服务端账号相符才放行。
- local-runtime 继续在统一工厂注入平台、完整会话、通用话术、压缩、trace 和确认门；托管 complete 走受限客户端 API。traceId 只在本机 options 转发，不发送给服务端；只有实际聊天 fetch 前发出提交证据，刷新令牌不冒充 AI 请求。
- 托管摘要与正文都属于模型调用，可能分别消耗试用次数；使用服务端的输出/消息限制，失败继续拒绝超限请求，不退回本机 Key 或重发。调试区的模型来自实际账号能力，而不是残留的本机模型配置。

## 验证与运维

先 npm run server:verify，再 npm run check、npm run test:desktop。原生检查用隔离 SQLite 和模型夹具；桌面检查用真实 Electron/safeStorage、临时工作区与回环 HTTP 协议夹具，不登录生产账号、不用付费模型、不发真实买家消息。MySQL/PostgreSQL、真实各厂商和线上 OAuth/邮件需单独验收，不能用上游历史 CI 冒充本次执行。

测试入口只通过 createLocalRuntime 的显式依赖参数注入，不提供生产环境变量或渲染层覆写网络目标。server/scripts/verify.ts 是独立构建工具，另有 TypeScript/ESLint 检查；导入代码由来源清单和原生构建/测试检查，桌面自有新代码继续使用 TypeScript。

切回本机模式并重启可继续使用原本机资料和密钥；托管工作区保留供原账号再次授权使用，不复制或覆盖。生产服务部署、DNS、证书及既有线上数据不由合并和本机测试自动修改。维护修改前必须读 server/CONSTRAINTS.md，禁止将生产初始化脚本用作测试。

## 2026-11-16 服务端模型范围

管理后台“试用设置”新增可用模型范围：全部已启用模型、指定多个模型。全部指当前托管连接目录中 ready 的连接，新启用连接自动纳入；不包含未配置的服务商。指定模式至少选择一个模型，默认模型必须在范围内。账号指定模型仅作为默认偏好：不可用或不在范围时，依次使用可用的全局默认、按模型 ID 排序的首个可用模型。没有可用模型时接口明确返回 model_not_ready。

策略字段为 `model_scope: "all" | "selected"`、`allowed_models: string[]`；原 `default_model` 保留。旧策略未设置范围时继续单模型行为，旧管理接口省略范围时保留已保存范围。管理员可保留临时失效的历史默认并修改额度；范围中引用的连接须先移出范围、解除默认和账号引用后才能删除。

客户端配置接口返回安全的 `models: [{id,name}]` 和有效 `default_model`。聊天接口新增可选 `model`，只能选列表中的模型；未传使用默认，显式选范围外或已失效模型拒绝，不静默换模型。同一 `client_request_id` 改选模型会返回 request_conflict，旧无模型请求的摘要保持兼容。渠道绑定、计费和限流仍使用原流程。

此次只交付服务端、原生管理后台和接口契约。现有桌面 `managed-session.cjs` 不转发 model、没有托管模型切换入口，仍调用服务端默认模型；桌面多选交互需后续接入，不能将此次接口测试当作桌面切换验收。识图能力仍受现有托管能力约束。未部署生产服务或修改本机实际策略。

## 1.0.18 人民币估算与多模型整合（2026-11-16）

沿用现有 New API / Gin / GORM 管理入口、二次验证与审计；金额计算复用固定上游已有 shopspring/decimal v1.4.0，不引入计费平台或另起钱包。

- 模型配置中每个 API 可填写输入与输出单价，单位人民币元/百万 Token；两项同时留空表示未配置，两项显式 0 表示免费。非负、最多 6 位小数、最大 999999.999999。
- 新调用接纳时冻结价格和实际模型，包括“未配置价格”的状态。后续调价不改旧快照。修改单价不重新检测供应商，不修改密钥、额度和余额。
- 既有调用有实际渠道和模型且与当前配置价格完全匹配时，可按当前价格回算，显示“按当前单价回算”；渠道未知、模型不符、没有价格或没有供应商返回用量均不计价。未知不当成零元。
- 概览、每日明细、账号汇总、逐次记录显示人民币估算、已计价/未计价调用和回算数量。使用精确十进制字符串传输；显示到 6 位小数，微小正金额显示 < ¥0.000001。
- 固定单价估算没有实现供应商缓存折扣、分时/阶梯、优惠券或税费，不等同于供应商账单，也不扣用户余额。DeepSeek/Qwen 的实际费率须由管理员依据采购方案填写。既有按次账本与原生钱包保留。
- 数据库仅新增模型价格与调用快照字段，既有行保留；无数据清除、密钥迁移、知识审核或消息发送。
- 整合已完成的多模型权限范围迁移，同时保留受限 PNG / OCR 兼容。生产更新仍按 server/AGENTS.md 单独授权，不因源码合入而自动部署。

参考核查：[New API 定价](https://docs.newapi.pro/zh/docs/guide/feature-guide/user/pricing)、[DeepSeek 定价](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)、[Qwen3-VL-Plus](https://help.aliyun.com/zh/model-studio/qwen3-vl-plus)。原生定价是配额/售价用途，本功能分离为管理成本估算，避免把钱包金额误认作供应商成本。

## 2026-11-17 服务端上下文策略执行

托管聊天接口在原请求体上增加三个可选字段：`purpose` 只接受 `reply`/`learning`，`policy_version` 只接受非负整数，学习调用必须携带 `learning_source`（`pdd_detail_text` 或 `pdd_detail_image`）。`null`、字符串、小数、负数、未知 purpose 或未知来源均按无效请求拒绝，不会进入额度预留。省略全部新字段的旧调用保持原请求摘要和回复行为；显式 purpose/version/source 参与请求摘要，因此同一 `client_request_id` 不能改用途、版本或来源后复用旧结果。

显式 `policy_version` 与服务端当前策略 revision 不一致时，在预留额度前返回 409 `policy_version_stale`。已成功请求的原样重放在策略更新后仍按原摘要返回缓存结果，不重复扣减试用次数。学习调用还要求 `learning.enabled=true`、来源在 `allowed_sources` 内、账号已启用，并受策略视觉开关和获准通道真实上游模型能力约束；图片 parts 必须与声明的文字/图片来源一致，否则返回 400 `learning_source_mismatch`。关闭时返回 403 `learning_disabled`，来源未允许返回 403 `learning_source_not_allowed`，策略禁用图片学习返回 403 `vision_disabled`，非视觉上游模型沿用 400 `vision_unavailable`。客户端声明的来源只是声明，服务端不能证明商品页面的真实来源，也不宣称已抓取或验证买家页面。

客户端提交的 `max_tokens` 不参与上游请求。回复沿用试用策略的 `MaxTokens`；学习使用策略 `max_output_tokens`（512..4096，可高于旧的 512），但不会突破策略上限。接待新规则启用时，服务端把 `runtime_context.system_prompt` 作为首条 system 消息只发给上游，客户端配置、错误和调试日志都不返回该文本；固定上游 logger 的 `lingtu_internal` 替换保证 DebugEnabled 时请求字节被替换为 `managed relay event`，未修改生成的上游源码。模型完整回显规则或较长直接片段时，响应清洗失败关闭；语义改写不能可靠识别，管理员不得把密钥或凭据放入提示词。

显式 policy-aware 调用，以及已启用隐藏接待规则的旧调用，按获准通道实际上游模型使用既有 tokenkit 估算文字输入，包含隐藏 system prompt、排除 base64 图片，超过 16384 token 在预留前返回 400 `context_too_large`；未启用规则的旧调用保留既有上限。图片仍沿用既有 PNG/尺寸/数量校验。策略记录损坏时所有调用返回 503 `configuration_unavailable`，避免默默绕过管理员已保存的接待规则。`managedUsage` 增量 `purpose` 列由现有 AutoMigrate 迁移，账号日额度、并发、结算、成本、不确定结果和模型准入不变。

本机隔离测试覆盖上述分支及既有 chat/idempotency、vision、client projection 回归；未部署生产、未调用付费模型，也未验证真实商品页面来源或供应商实际计费。
