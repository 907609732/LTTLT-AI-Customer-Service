# 自带模型密钥模式接入说明

## 当前选择与来源

默认本机模式使用用户自己的 AI 密钥，无需注册软件账号；托管模式由用户显式选择并授权，详见 MANAGED_SERVICE.md。两种模式均需单独完成店铺平台登录，本机模型费用由用户自己的服务商账户承担。工程根为 F:\Setupgod\yunduo-ui，目录边界见 PROJECT_LAYOUT.md。

复用 PR18 的固定提交 `5b6293cc9c75e6e25fdaa16d6187effb0a9d1a5e`，包含其依赖的 PR16 后端基础。来源、许可证和源码清单见 `vendor/lingtu-runtime/PROVENANCE.md`、`source-files.json`。不复用 React 界面或启动旧 renderer，也不修改本机其他仓库、店铺软件安装目录或既有客户数据。

## 从哪里开始使用

1. `npm ci`，运行 `npm run electron:dev`（开发）或 `npm start`（构建后运行）。浏览器 `npm run dev` 仅供预览，不保存业务数据。
2. 打开“设置 / 模型与本机设置”，选择服务商预设或自定义接口，填写自己的 Key。模型名称与地址可按服务商授权修改。点击“测试连接并保存”会向你配置的模型发起一次实际连接测试。
3. 在“店铺与商品”添加店铺。当前注册平台为拼多多网页版、抖店客户端，以及只在桌面版出现的“本机模拟店铺”。添加记录不会登录店铺，也不会开启 AI。想先把回复流程走一遍，可以选“本机模拟店铺”并起个名字（必填，例如：本机演练店）。
4. 在商品知识中录入本店资料，或先预览再确认导入 CSV。在意图问法中保存知识包，明确勾选应用店铺和可选商品编号。
5. 进入训练场，选择店铺后输入模拟问题，验证规则与知识。训练调用已配置的模型，不向买家发送。
6. 回到工作台，在未登录列表打开平台工作台，由用户完成平台登录。确认消息采集和店铺身份后，按需逐店开启 AI。

7. 点击标题栏“日志”查看买家/客服消息及 AI 实际上下文。AI 生成后自动弹出待确认窗口，逐条点击确定才发送；取消、关窗或过期不会发送。当前审批模式停用自动超时兜底，转人工提示也需确认。详见 RUNTIME_LOGS.md。

8. 想先演练再接真实店铺：侧边栏「开店准备 → 模拟客服台」（路由 `/sim`）选择本机模拟店铺并「打开店铺」，再点「打开模拟顾客页」。主进程会给出形如 `http://127.0.0.1:43100/?token=…` 的地址，贴到浏览器打开即可扮演顾客：页面可新增、改名、删除模拟顾客（默认三位），以顾客身份发消息；桌面端客服台可查看会话并逐条确认回复（AI 候选同样需要逐条批准）。该通道只在本机运行，没有真实平台登录、没有真实买家、也没有平台送达，页面与界面都标注了这一点。

抖店使用本机客户端及桥接；本机需具备匹配的客户端和桥接能力。未连接时明确显示等待/失败，不能把“成功添加店铺记录”当作平台已经接通。此集成未提供新的原生客户端注入安装器。

## 维护接线

新增直接依赖：Zod 4.6.7 用于运行时校验，MiniSearch 7.2.0 用于本机中文知识检索，PapaParse 5.7.1 用于 CSV。版本与固定上游一致，均锁定在 package-lock.json；未新增模型 SDK、数据库或账号服务。第三方许可随 vendor 中的来源文件保留。

- 原始运行时在 vendor，仅作为受审查依赖；app/main.ts 装配 Pinia 和服务。
- `electron/local-runtime.ts` 默认创建本机工作区，显式托管模式按来源与已验证账号隔离；`business-ipc.ts` 对可信应用主框架提供 snapshot/execute/event/present-store。
- `shared/contracts/backend.ts` 定义业务快照、白名单命令及 DTO 校验；快照剥离未知字段，不携带密钥原文。
- `shared/platform/backend.ts` 适配桌面桥；`shared/state/runtime.ts` 订阅快照、丢弃迟到刷新，持有跨页面店铺选择。
- 商品领域服务负责分页转换与 DTO 校验，其余模块通过统一运行时命令访问对应本地服务，禁止组件直接访问网络、存储或 IPC。
- 保存操作保留版本字段。外部更新后不要无条件覆盖用户草稿；发生版本冲突时让用户显式载入最新数据。
- 主应用只运行一个实例，退出时停止引擎、采集和平台视图。每次启动将 AI 置为关闭。

## 数据与凭证

生产数据位于 `app.getPath('userData')/local-runtime`；默认保持 `%APPDATA%/yunduo-ui-restored/local-runtime`，由 electron/app-identity.ts 显式兼容，不根据“灵兔 AI”新名称创建空目录。显式 --user-data-dir 仍优先，用于隔离验收。与原 desk-v1、其他灵兔工程及其他软件目录隔离，不自动迁移旧数据。

Key 通过 preload 的白名单调用一次性送到主进程，经 Electron safeStorage 加密保存为 secrets.json。系统加密不可用时拒绝保存，封住上游 SecretStore 的历史 base64 降级路径。UI 只显示“是否已配置”，成功后清空输入框，不回填旧 Key。不要读取或打印开发者环境密钥，不把凭据写入 VITE\_\*、日志、截图、源码或测试报告。

自动桌面验收通过父进程创建临时目录，隔离 Electron 用户数据和业务文件，进程退出后清理。`YUNDUO_SMOKE_DATA_DIR` 只属于测试工具，生产入口不读取此变量。

本机模拟店铺的记录写在同一个本机工作区的 `simulator-stores.json`（顾客、消息线程、事件序号），不写平台目录、不联网。模拟顾客页只在用户点「打开模拟顾客页」后启动，只监听 127.0.0.1 的 43100～43104 中的第一个可用端口；访问需要本次运行生成的一次性口令（只存在于主进程内存和用户复制的那条链接里），页面响应带 CSP、`no-store` 和 `nosniff`，所有 `/api/*` 都校验口令。桌面端退出或重启后旧链接立即失效，需要重新打开获取新链接。旧链接或漏掉口令时，浏览器会看到一张 403 说明页（指引回桌面端「打开模拟顾客页」重开），页内不出现尝试过的口令，`/api/*` 仍返回 401 JSON；口令错、缺失、过期表现一致，能否进入只由桌面端决定。

## 验证与边界

日常只检查本次改动及直接影响的类型、文件和测试；界面改动只验收受影响界面。仅打包 Release 时运行全量 `npm run check`、`npm run test:desktop` 和上游回归，以根目录 AGENTS.md 的用户验证规则为准。桌面专项可复用真实运行时、主进程、preload 和 Vue 页面，在隔离目录用合成商品、会话和本机 HTTP 模型验证接线。

想确认“界面真的能被点开、顾客页在真浏览器里真的能用”，额外跑 `npm run verify:cdp`：它先用 `build:desktop` 重打包主进程，再起带调试端口的真实 Electron 窗口和真实 Microsoft Edge，用 DevTools 协议点击按钮、填输入框、截图（加模拟店铺 → 打开模拟顾客页 → 顾客发言 → 桌面端确认回复 → 顾客页收到回复 → 无口令被拒）。需要 Node ≥ 22 与本机 Edge，端口 5173/9222/9333/43100 空闲；它不属于 `npm run check`，一次运行约 20～40 秒，证据写在 `artifacts/cdp/`。

测试证明模型请求协议和本地业务链路，不证明真实视觉识别准确率或真实平台稳定性。没有登录真实店铺、读取真实买家照片、向真实买家发送，或调用用户的付费模型。平台网页升级、客户端版本和账号权限仍需用户在真实环境验收。
