# 云朵配置中心复用核查

用户确认有复用授权，但没有原始项目源码。2026-11-09 从本机云朵客服 5.2.6 安装包的 ASAR 提取渲染资源进行离线分析；这些文件和可读化输出只保存在工作区外的 `_research/yunduo-renderer`、`_research/yunduo-config`，未加入本仓库。使用 Wakaru 将配置中心压缩模块可读化；恢复结果不是原始源码。

## 已验证

- 原配置中心是 Vue / Element Plus，灵兔客户端为 React / Electron，不能直接当 React 组件引用。
- 用隔离浏览器运行提取的渲染资源，拦截所有非本地网络请求；通过仅含测试数据的 `yunduoDesktop.store` 对象，可以显示店铺和原“转接人工”页面，读取模拟关键词，并观察“保存设置”调用模拟接口及其字段。该验证未连接真实店铺，也没有验证数据落盘或实际接待。
- 原页面依赖 `listStores`、`getKefuSettings`、`saveKefuSettings`、`getAutomationRules`、`saveAutomationRules` 等接口。真正的运行逻辑并不都在页面模块内，不能把渲染代码复制过来就视为业务接通。
- 安装包的主进程实现显示，客服设置和自动化规则经云端店铺配置服务读取、保存；安装包没有提供该云端服务的源码。实际业务还依赖云端配置和各平台适配，不能把云朵账号或其服务凭据直接接到灵兔。
- 灵兔现有 `UX08` 全局关键词由回复引擎读取；命中时发送配置的话术、标记会话并暂停该会话 AI。当前没有平台客服之间的自动转接操作。

## 当前实现范围

关键词编辑从模型接口弹窗移至灵兔现有配置中心；保存仍走现有全局 `save-config`，不修改原有数据结构。页面提示平台自动转接未接入。浏览器端到端检查使用模拟的灵兔桥接，验证输入、保存命令、刷新回读及与模型设置分离，并未证明真实平台操作。

## 后续接入边界

需要逐项核对原页面接口参数、返回值和运行时业务依赖，设计受限桥接并对接灵兔的真实服务。店铺级配置与现有全局关键词不能直接等同；欢迎语发送、自动操作、图片识别、知识库、工单和质检等能力仍需实际实现及隔离数据验证。不要给未接入的按钮显示保存成功，也不要将第三方网络或认证信息直接带入客户端。正式发布前还需保留适用的第三方版权与授权说明。
