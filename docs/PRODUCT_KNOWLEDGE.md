# 商品知识界面与交互优化（2026-11-14）

依据用户两张参考截图，规划、UX、UI专家已顺序核对。复用现有Vue/ElementPlus2.8.8和商品服务，不新增生产依赖，不复制其他软件代码或演示数据。

商品页仅管理当前店铺：返回店铺按钮置于内容区顶栏，移除大标题、维护说明和当前店铺选择行；采集平台商品位于新增商品知识左侧，直接启动并显示进度。商品列表卡片保留双搜索、本页勾选批量编辑、平台编码只读、确认删除、真实启用/停用状态、分页和CSV二级弹窗。编码与平台商品编号不同，不用启用冒充已学习。

商品采集复用现有平台学习任务、原生拼多多分页读取和本地save-product服务。每页身份核验后、游标持久化前，将来源商品保存为停用商品行，同时保留独立问答候选审核流程。已有平台商品编号跳过，保护人工编辑；没有可靠来源的价格留空。整页先验证字段长度，超限如实失败而非静默截断。保存前后检查账号、工作区、店铺与取消状态；部分失败后刷新真实已保存行，重试按编号去重。重启后适配器未建立时复用正常打开店铺流程，继续使用原登录分区；未登录或验证码仍需用户完成。

平台来源采用自有TS按店铺独立JSON原子保存与有界缓存，保持vendor/Product原结构不变。全店搜索在主进程通过已有真实分页读完且核对revision/total后筛选分页；10000上限，不用本页筛选假全店结果。批量商品更新复用逐条版本检查，部分失败如实列明；跨店/工作区切换丢弃迟到响应、停止余下操作。CSV保留原格式，不包含平台来源档案。

## 平台编码与SKU修正

上一版所谓商家编码实际是本机自定义元数据。现已移除其单条/批量设置入口，目录编码改从平台来源档案读取；旧product-codes文件保留，不冒充平台值，旧写命令明确拒绝。商品及SKU编码、SKU ID、sku69_code条形码独立保存；未采集与平台未提供分别显示。

采集逐项点击平台原生编辑入口，只读取表单，不点击提交或保存草稿。独立窗口复用店铺分区，严格校验固定详情路径、goods_id及账号/店铺；通过页面自身原生响应取得真实SKU ID、编码和条形码，再按规格名称/值组合与DOM表格交叉核对价格和当前库存，不按行序合并。详情文字、属性和图片来源保留在platform-products店铺档案，图片不做OCR。重新采集会更新来源档案，不覆盖已有手工知识或启用状态。

平台明确返回900009（禁售不可编辑）时，只跳过该商品详情并保留原来源档案；仍读取其列表行，任务标为部分完成、显示受限商品及原因。其他验证码、身份、权限、未知错误不能当作禁售跳过。支持原生固定表头和独立滚动表体，SKU完整性仍与原生响应数量/规格组合交叉核对。

平台详情弹窗展示全部SKU及采集时间。启用仍是显式动作：编辑打开“用于商品知识检索”，或勾选商品后批量修改使用状态。保存即更新本店检索，无需训练模型参数。正式回复与训练均经product-spec-context：已核实商品和明确SKU/平台编码/条码/唯一规格组合才提供对应SKU，未知或不明确组合要求澄清；价格库存仅为快照。关联平台商品的旧全文商品命中会被结构化规格来源替换，避免旧规格信息混入；独立手工商品仍走原检索。
