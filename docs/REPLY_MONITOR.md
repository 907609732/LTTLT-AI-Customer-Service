# 回复监控会话视图

## 目标与布局

`/reply-monitor` 是工作台和配置中心左下“回复监控”共用的 340×300 紧凑子窗，仍由 `electron/reply-monitor-window.ts` 跟随主窗口左下角、`showInactive` 显示且不全局置顶。内容顺序为：

1. 店铺 / 买家标识和发送模式；
2. 当前咨询商品摘要；
3. 当前会话气泡区（独立滚动，默认滚到最新一条）；
4. 单行 AI 状态和一眼可见的原因；
5. 原有的“高级日志”、待确认候选的“取消 / 确认发送”以及源码版“开发调试”。

展开 960×620 时左侧仍固定 340px，GM/CMD 只在右侧；关闭、收起、尺寸和终端生命周期均沿用原窗口实现。

## 会话与气泡

- 会话只按 `storeId + uid` 精确匹配，绝不把另一店铺或另一买家的同名字段拼入。
- 买家消息在左，已采集的我方客服消息在右；系统消息居中，未知来源也居中显示“未识别来源”，不冒充买卖方。
- 候选状态单独显示，不与真实消息混为一类：
  - `pending`：候选 · 未发送；
  - `sending`：候选 · 等待回执；
  - `failed`：候选 · 发送未确认；
  - `sent`：候选 · 平台已确认（归档尚无同文卖家回显时才显示，有真实回显时不重复气泡）。
- 已取消、已失效的候选不进入气泡区；仍可从原日志/候选状态查看。
- 气泡区是独立的 `overflow-y: auto` 区域，商品摘要在其上方，状态/原因和底栏不随气泡滚走。

## 当前咨询商品

商品卡只消费真实生成链路的最小投影：

- `ReviewConsole` 从模型 trace 的真实 `reviewContext` 读取 `productId` 与平台行已有的 `goodsTitle`；候选创建时只复制同店同 UID 的 trace 商品。
- 标题/图片优先由主进程按同店精确 `productId` 查询现有知识绑定或平台商品详情；没有资料时保留页面标题，或只显示编号。
- 只有平台详情里现成的 HTTPS 图片才显示，不生成占位图、不把图片 URL 当已识别图片内容。
- 没有候选时，仅在同一会话、且 trace 不早于最新买家消息时展示最近一次生成商品；新买家消息后的旧商品不会被冒充为当前咨询商品。
- 不从模型正文、推荐商品、商品目录或跨店/跨买家数据补全。缺失时明确显示“当前咨询商品未识别”。

## 只读与保留能力

监控不提供编辑、删除、质检、重试发送或任意平台操作。确认/取消仍走原 `review-reply` 统一确认门；关闭窗口、查看日志、展开调试都不构成批准。商品摘要只用于识别当前咨询对象，不改变模型上下文、发送内容或审核策略。

## 验证

相关测试覆盖跨店铺同 UID、买卖方/系统/未知来源、候选与真实回显、失败/发送中状态、商品同店隔离、缺失未识别、图片 HTTPS、原因只输出一次和独立滚动：

```powershell
npx vitest run tests/reply-monitor-conversation.test.ts tests/reply-monitor.test.ts tests/reply-monitor-developer.test.ts tests/reply-monitor-window.test.ts tests/review-console.test.ts tests/review-engine.test.ts
npx tsc -p config/tsconfig.electron.json --noEmit
npx vue-tsc --noEmit
npm run build
```

已知限制：没有真实店铺验收；商品标题/图片取决于已采集的平台商品详情或已有知识绑定，平台未提供时仅显示编号/页面标题或未识别；会话归档可能晚于实时日志，此时先显示真实消息事件，收到快照后自动切换为归档气泡。
