# 客户端请求误占后台登录限流（2026-11-10）

## 原因与修改

日志确认客户端 `/api/client/me`、刷新、退出请求先出现 429，随后后台 `/api/user/auth/refresh` 和 `/api/user/login` 被拒绝。原先整个 `/api/client` 组误用原生 `CriticalRateLimit()`，与后台登录共用每 IP 20 次 / 1200 秒的 CT 桶。

修复复用 New API 原生内存/Redis 限流器，不新增限流依赖：客户端组改用现有全局 API 配额；设备授权、轮询和刷新独立 LT 桶，分别为 10、120、120 次/分钟。后台配置保存和设备审批独立使用原有关键操作限额。原生登录的 20 次 / 1200 秒保护不变。

原生限流响应保留 429 和 Retry-After，增加安全的本地化 message_key 与 rate_limited 错误码。网页以中文或所选语言展示提示。原生 API 与客户端仍共享既有 GA 全局限额，这是总流量防护，未取消。
