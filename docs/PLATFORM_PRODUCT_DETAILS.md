# 平台商品详情、SKU与AI检索实施计划

目标：平台商家编码只读采集，保存商品详情、SKU规格及独立条形码，AI按商品和明确规格使用资料。用户已确认按上一轮提出的方案实施。

复用现有Electron原生平台窗口、DOM/原生查询观察、Zod、商品服务与模型上下文注入，不引入第三方账号或私有接口重放。比较过[拼多多PHP SDK](https://github.com/asialong/pinduoduo-sdk)和[Go接口项目](https://github.com/dtapps/pinduoduo)的接入方式；其开放平台授权及PHP/Go栈不适合当前已登录桌面采集，因此不引入代码或新增许可证依赖。条形码仅在来源确实提供时采集；编码、SKU ID、条形码分字段，不互相推测。已有本机自定义编码保留原文件，不再标成平台编码。

- [x] 确认实店原生商品详情、SKU字段和可访问范围；建立明确失败、身份和取消检查。
- [x] 添加受校验的平台商品来源档案，按账号/店铺隔离，原子保存，商品行仍由已有服务管理；不覆盖手工知识或自动启用。
- [x] 将目录编码改为平台来源只读值，新增详情/SKU展示和缺失来源提示，移除平台编码编辑入口。
- [x] 将结构化规格资料接入正式回复和训练共同的检索链路；显式规格匹配、未知规格澄清、跨店隔离、停用不使用。
- [x] 针对性测试先失败后实现；源码构建、实店只读采集、隔离本机模拟模型验证不同规格；不使用真实买家或付费模型测试。
- [x] 更新交接并审查改动，记录实际来源缺失和未验证项。

验收以平台真实可访问字段为准；图片详情保留来源，不将未识别图片冒充文字事实。商品动态价格、库存仅作为采集时快照。

实店结果：10个商品，9个可读详情、57SKU及57真实SKU ID；1个商品禁售返回900009，仅其详情被跳过并标记partial。条形码源字段均为空；以合成正例验证前导零、独立字段及不借编码。固定表头与虚拟滚动实店原先仅显示14行，现滚动合并并核验全部22SKU，未降低完整性要求。新来源已保存，真实商品仍全部停用。

AI结果：实际采集的A款/B款/编码A/未知Z款/未指定规格5场景通过真实AiClient+受控本机回包的正式请求验证。A款19.90元、B款18.00元，SKU ID/编码不混用；未知规格提供澄清约束。此为actual-source controlled-model，不是外部模型语义评测。来源及报告在忽略目录artifacts/product-details-acceptance，未修改真实启用状态或发送消息。

最终范围验证：12文件118项相关测试、完整类型、限定lint、格式/边界和构建通过；隔离三进程16场景通过。没有运行Release全量检查或打包；没有生产部署、正式收款或买家发送。
