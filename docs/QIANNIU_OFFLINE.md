# 千牛离线接待验收与实店接入条件

1.0.60 已找到本机真实运行时并接入客户端入口，当前说明见 [QIANNIU.md](QIANNIU.md)。下文为 1.0.59 离线专项的历史范围；其“尚未找到实店组件／必须先提供官方接口”不再作为当前接入限制。

## 复跑

从灵兔仓库根目录执行。使用工程已锁定的 Node/Electron 工具链（Node ≥ 24），由验收脚本读取本机用户提供的交付包：

```powershell
npm.cmd run build
npm.cmd run verify:qianniu-offline -- F:\Setupgod\qianniu-delivery
```

脚本在新的系统临时资料目录启动独立桌面实例，退出后清理本次目录。截图和断言报告保留在 `artifacts/qianniu-offline-<时间戳>/`，正文、店铺和买家均为合成数据。重复运行生成新证据，不覆盖前一次结果。普通桌面和安装包不会启动这套测试。

## 接线与约束

- 只从交付包读取 `@qianniu/harness@0.2.0` 的 `SidecarClient`、`MockSidecar` 和它们的事件依赖，导入前核对三份源码 SHA-256。交付包不复制、不修改、不视为灵兔自有源码；哈希变化时先审查，不关闭校验。没有新增依赖、环境开关、IPC 或生产存储。
- 两个 mock HTTP 端口和模拟模型都由验收进程在 `127.0.0.1` 随机分配；SDK 客户端仅访问这次的四个模拟路由，不跟随重定向、不重试。没有真实端口配置、客户端启动、注入、登录、凭据读取或外部网络连接入口。
- 用 `/popPending` 的合成买家文字进入灵兔 `sim-local` 队列，复用真实消息监控、会话归档、模型请求、日志和统一审核。AI 关闭仍收件；不把卖家消息当买家输入，同一买家同一模拟消息 ID 去重。`/chatHistory` 给审核前后提供同一合成会话的正文基线，读不到时不能批准。
- 审核走真实 Vue 小窗／日志按钮与原 IPC，不在 SDK 自动回复。实际尝试发送才调用模拟 `/textToSend`；必须在 `/popOutbound` 读到本次 ID、买家、会话和正文一致的卖家回显才记为**模拟收到**。核对历史失败保留候选，不向模拟顾客发送。回显缺失显示「需核对发送」，不自动重发。回显关联 ID 是本轮 mock 补充，**不是**已核实的实店接口字段。
- 正式版「千牛店铺」仍为「开发中」。离线命令不提供实店注册、收发、AI 开关记忆、商品订单、转接、图片视频或模式自动切换。

## 实店接入还缺什么

1. **已获授权的消息通道。** 交付目录只有资料、SDK 和 mock，不含官方千牛、可运行的实店消息服务或授权。先拿到应用实际获准使用的接收、读取会话／历史、审核后发文字及发送结果能力，及测试店铺、客服子账号。参照[千牛客服面板插件接入](https://developer.alibaba.com/docs/doc.htm?articleId=119210&docType=1&treeId=801)和[奇门官方场景接入](https://developer.alibaba.com/docs/doc.htm?articleId=106849&docType=1&treeId=796)确认可用场景。公开的订阅和异步机器人接口不等于本应用已获消息权限，也不保证支持灵兔外部逐条审核或允许所需等待时长。
2. **经官方或已获平台授权的提供方确认的契约。** 需要脱敏的入站、历史与最终回执样例，明确店铺／子账号／买家／会话／消息 ID，取消授权、断线、重复投递、乱序、回复时限、幂等和不确定结果的处理。提交被受理不能当作买家收到。凭据由主进程或经授权的服务端专门保管，不放入聊天、截图、源码、模型请求或日志。
3. **分阶段验收。** 先用沙箱或专用测试店只读接收和复核，再在用户明确允许时，点击确认发送一条指定测试消息并核对平台回显；另外验证取消、过期／新消息、客服接管、店铺切换、断线、同条重复审批及无回执均不会误发或重发。确认不支持延迟审核时保留仅生成草稿，不用自动应答替代。暂不要求订单/商品/转接权限。

下一步请提供开放平台里已开通的**权限名称和对应文档**，或已获授权的消息提供方及其测试接口契约，不需要发送 Key、密码、Cookie 或任何真实买家记录。
