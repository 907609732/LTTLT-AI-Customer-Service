# 架构决策

## 2026-11-12：恢复已归档聊天上下文

用户的实际请求日志证明模型仅收到最后一句。原因是上游历史 HTTP 不可用时只剩队列批次，已有归档未参与生成。生产注入 TypeScript 组装器，按店铺和买家读取最新归档，合并平台历史与当前消息，取消生成前的 20 条截断，再由既有 16K/8K 机制控制长度。相比仅增大平台接口 limit，这种方案能在接口不可用时继续使用已经采集的聊天；不尝试猜测平台未返回的记录。

此决策替代本日早期“保持最近 20 条窗口”的限制，不改变归档最多 100 条和 200 会话的现有持久化边界，不缓存跨会话摘要，不将未批准候选放入历史。后续若需更早记录，应先确认平台历史契约与数据保留策略，再实现分页采集并独立验收。

## 2026-11-12：逐条消息解释未调用 AI 与开放回复间隔

用户要求在买家消息上看到是否调用 AI 及未调用原因，并能调整 60 秒间隔。新增有界证据跟踪，区分采集、调度、准备、真实 HTTP 发起、正文完成及发送确认；不恢复限流刷屏，不从现有开关推断历史事实。只读 worker 观测限于主进程，不暴露运行时对象。

修正新消息使旧候选失效后仍永久人工暂停的路径，保留显式取消与人工接管。间隔通过独立表单及受限配置适配修改，默认值保持 60，0 可关闭，不代替其他安全检查。

## 2026-11-12：去除轮询噪声并计量 AI 回复耗时

按用户要求不保存高频 reply:throttled 轮询记录，而非仅在 UI 隐藏；限流与真实异常保留。计时从模型生成入口而非买家消息时间开始，到正文完成为止；使用单调时钟，包含准备和压缩，排除人工确认与平台发送，避免将人等了多久混入模型耗时。摘要回合单独标示以便定位时间来源。

## 2026-11-12：确认后逐字输入再发送

按用户要求将整段填入改为逐个可见字符追加，默认 50ms，仍是网页内操作，不使用系统键盘或系统鼠标。保持明确批准，完成输入后才点击发送；取消信号、买家变化、网页新消息和人工编辑均阻断。采用字素分割以避免组合 emoji 被拆开。输入中止保留草稿供人工核对，不自动删除用户内容。

## 2026-11-12：发送确认区分新消息与历史不可读

用户实测确认后反复提示“已有新消息或无法核对历史”。审查发现原确认依赖可能不可用的私有历史 HTTP 请求，并跨来源强比较消息 ID/时间。改为生成前采集网页基线、确认时定位同一买家核对有序正文及媒体，绑定页面实例；元数据补全不作新增。读取暂时失败保留候选，不让用户不断重新生成并支付模型费用；不移除真实新消息、人工回复和停店检查。

## 2026-11-12：16K 触发并压至约 8K

采用同模型语义摘要，更早对话和检索资料压缩，系统规则、近期原文和图像输入保持；失败时停止，不以丢弃受保护资料或发送原超限请求兜底。每请求独立计算，避免摘要缓存跨店或在规则修改后过期。原先保持的 20 条窗口已由本页“恢复已归档聊天上下文”决策替代，不声称拿到了未采集的平台历史。

选择 js-tiktoken 1.0.21 lite 的本地 cl100k_base 作为统一计量口径，按 16,384/8,192 执行；跨供应商和图片 token 存在差异，界面明确标注估算。摘要调用会增加费用，自动测试仅使用本机夹具。摘要及最终请求分开记录，正式发送审批不变。

## 2026-11-12：拼多多采用网页按钮发送

用户明确要求浏览器内置操控式点击，不操作系统鼠标。查明上游当前 PddWebAdapter 实际发送路径为浏览器原生回车事件，因此在本工程 TypeScript 装配层替换文字发送策略，复用已有 DOM hook，并收紧为按钮单击、不补回车、完整正文校验及真实回显核对。原上游适配器默认行为保留，其他平台不受影响。

由于上游注明平台可能拒绝脚本 click，实际采用 DOM 定位按钮后通过浏览器内部鼠标事件触发可信点击，不移动系统指针；守卫验证买家、正文、目标按钮及操作令牌。不发送回车。离线夹具仅验证接线和防重复行为，实店可用性单独验收。

## 2026-11-12：实时调试及逐条批准 AI 回复

按用户要求使用独立原生日志窗，避免店铺 WebContentsView 覆盖 HTML 弹层。通过主进程内存记录已采集消息和实际模型 messages，不读取 HTTP 凭证、不新增敏感上下文落盘。固定容量与截断说明保证长时运行不会无限增长。

确认门位于原引擎统一发送入口、欢迎语处理之后，复用发送节奏、台账和不确定结果隔离。没有选用“生成后转成人工 send-reply”方式，因为那会绕过原引擎台账并容易重复发送。每条候选只能批准一次；拒绝、过期或上下文改变不发送，启动不恢复任何批准状态。自动超时兜底停用，转人工提示亦经确认。

## 2026-11-12：先建立接入边界，保留界面兼容层

沿用现有 Vue/Electron 技术，不建立多仓库或微服务。源码按 app/modules/shared 整理，跨模块经公开入口；Electron 拆分窗口、IPC 和 preload。选择 TypeScript 发现原还原数据里的类型错误。

旧 CSS 和 data-v 标记保留，修复明确语法问题；逐模块有截图证据后再移除。避免目录迁移与全量视觉重写同时发生。

## 2026-11-12：交付范围按用户最新要求收敛

用户要求“修到能用，写好约束文档，开始对接功能”。因此优先稳定构建、入口、导航、业务占位和接入说明；不把全量语义还原作为开始接业务的前置条件。未确定的业务与演示字段在交接中明确登记，不能标记为完整产品能力。

## 2026-11-12：不通过占位提示接真实业务

全局点击兜底已移除。真实接入必须通过模块契约、服务与状态驱动页面，feedback 只负责显示明确的未接入提示，不承载网络请求。

## 2026-11-12：按用户选择接入自带密钥本地后端

固定复用 PR18 的 5b6293c，包含其 PR16 后端基础；保留当前 Vue 界面。上游 JS/CJS 存在 vendor，作为明确记录的第三方例外，通过哈希校验和上游测试维护；自有适配继续使用 TypeScript。

不连接上游账号、试用和额度服务。模型凭证由用户在桌面填写，主进程强制加密，不允许底层历史 base64 降级。自动验收使用临时目录和本机 HTTP，真实平台验收另记。

## 2026-11-12：识图复用当前多模态模型

按用户要求取消 qwen3-vl-plus 名称白名单，不新增独立视觉默认模型。仅放宽名称限制，不通过名称猜测真实视觉效果；接口和凭证就绪后允许每店开启，实际图片请求交给用户配置的模型，训练场负责验证。

选择在上游 createBackend 增加 local-only 可选能力策略注入点，自有策略写在 TypeScript；不采用仅修改前端快照的方案，因为保存和实际图片调用仍会被上游内部拦截。原始和实际哈希、补丁范围记录于 vendor 来源清单。默认上游策略和 managed 模式不变，升级时必须复核注入点。
